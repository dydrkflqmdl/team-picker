- **방 뽑기:** 참가자 메인의 방 뽑기 버튼은 지금 숨겨져 있고, 현장에서는 진행자가 **발표용 뽑기 화면**(`draw.html`)으로 뽑아요. 화면이 사람마다 같은 DB 함수를 대신 불러서 아래 규칙이 그대로 지켜져요. 한 사람은 **한 번만** 뽑을 수 있고, 다시 뽑으려면 진행자가 그 사람 방을 비운 뒤 발표용 화면에서 다시 뽑아요.
  1. 누를 때마다 **같은 성별에서 아직 방이 없는 사람 전원을 방에 넣는 계획**을 새로 세우고, 그 계획에서 내 방을 줘요. 이미 방이 있는 사람은 그대로 둬요.
  2. 기준은 두 가지뿐이에요: **남녀는 따로**, 같은 성별 안에서 **방 인원은 고르게**(차이 1명 이내). 그 밖에는 **전부 무작위**예요. 부서·직급·임원 여부·명단 순서는 보지 않아서, 같은 성별이면 누구나 어느 방에든 같은 확률로 들어가요(먼저 뽑든 나중에 뽑든 같아요).
  3. 가짜 29명(남 20·여 9, 부서 6개 — `tests/room-random/stats.mjs` 의 명단)이 한 명씩 무작위 순서로 다 뽑기를 4000번 시뮬레이션했어요(로컬 시험). 성별이 섞이거나 방 인원 차이가 1명을 넘은 적은 없었어요. 같은 방에 같은 부서 사람이 모이는 정도와 사람마다 방이 나온 횟수는 완전 무작위로 나눈 것과 같았고, 같은 부서가 한 방에 모이는 정도는 예전 규칙보다 크게 줄었어요. 진행자가 몇 명을 먼저 넣어 둔 뒤 나머지가 뽑을 때도 남은 사람은 누구나 똑같은 확률로 방이 정해졌어요. 다만 먼저 넣은 사람이 있는 방은 그만큼 덜 채워지므로 방마다 들어갈 확률은 다를 수 있어요.
  - 명단에 **성별이 없는 사람은 방을 뽑을 수 없어요**("진행자에게 말해 주세요"가 떠요). 뽑기 전에 성별이 다 들어 있는지 확인하세요.
  - ⚠️ 안 오는 사람이 명단에 남아 있으면 그 자리만큼 방 인원이 어긋날 수 있어요. 뽑기가 끝난 뒤 진행자 화면 객실표 칸의 **방 자동 섞기 · 안 뽑은 사람만**으로 채워요.
  - 여러 명이 동시에 눌러도 DB가 **방 뽑기끼리만** 한 명씩 차례로 처리해요(29명 동시 0.17초, 로컬 시험). 팀 뽑기와는 서로 기다리지 않아요.
- 팀은 한 사람이 **한 번만** 뽑을 수 있어요. 뽑은 팀과 **우리 팀 사람들**("지금까지 뽑은 N명")은 메인에 나와요.
- 팀 배정 방법은 이래요.
  1. 누를 때마다 **아직 안 뽑은 사람 전원을 가장 고르게 나누는 계획**을 새로 세우고, 그 계획에서 내 팀을 줘요. 이미 뽑은 사람은 그대로 둬요.
  2. "고르게"는 팀 인원, 임원, 부서마다, 남녀 인원이 4팀에 최대한 똑같이(차이 1명 이내) 나뉘는 거예요. 팀 인원을 가장 먼저 맞추고, 임원은 2배로 신경 써요.
  3. 고른 계획이 여러 개면 지금까지 뽑은 인원이 적은 팀을 골라요. 계획은 매번 무작위로 세우므로 결과는 랜덤이에요.
  4. 뽑는 도중에도 팀 인원 차이는 최대 3명까지예요.
- 임원은 직급에 대표·이사·고문·상무·전무·사장·회장이 들어가면 자동으로 판단해요.
- 29명 명단으로 400번 시뮬레이션한 결과예요(예전 규칙은 모두 고르게 나뉜 게 7%였어요).
  - 팀 인원 8·7·7·7, 임원 2·2·2·1, 여성 3·2·2·2(8명 팀에 3명)는 400번 모두 지켜졌어요.
  - 부서까지 모두 고르게 나뉜 건 98%였고, 나머지도 한 부서가 한 팀에 1명 더 간 정도였어요.
- ⚠️ **명단에 있는데 안 누르는 사람이 있으면** 계획에 잡아 둔 자리가 비어서 팀 인원이 어긋날 수 있어요. **안 온 사람은 뽑기 전에 진행자 화면에서 지워 주세요.** 이미 어긋났다면, 안 온 사람을 지운 뒤 인원이 많은 팀의 한 명을 **다시 뽑기** 하면 맞춰져요.
- 여러 명이 동시에 눌러도 DB가 **뽑기끼리만** 한 명씩 차례로 처리해서, 인원 균형이 깨지지 않아요. 메뉴 고르기와 진행자 저장은 뽑기를 기다리지 않아요.
  - 29명이 동시에 뽑아도 마지막 사람까지 0.2초 안팎이었어요(로컬 시험).
  - 그래도 사람이 몰려 DB가 시간 초과·잠금 오류를 내면, 참가자 화면이 0.5~2초 쉬고 최대 2번 자동으로 다시 보내요. 그동안 "사람이 몰려 다시 시도하고 있어요…"가 떠요.

## 처음 한 번 설정

1. Supabase 대시보드에서 **SQL Editor**를 열고 [`supabase.sql`](supabase.sql)을 통째로 붙여넣어요.
2. 붙여넣은 내용에서 `'여기를-바꾸세요'`를 **관리자 비밀번호**로 바꾸고 **Run**을 눌러요. **무작위 16자 이상**(영문 대소문자·숫자 섞어서)으로 정하세요. 진행자 화면 주소는 공개라 누구나 비밀번호를 대입해 볼 수 있어요.
   - 비밀번호는 저장소 파일에 적지 말고, 편집기 안에서만 바꾸세요.
   - 비밀번호가 틀렸을 때 일부러 늦추지 않아요. 그래서 길이가 유일한 방어예요(16자 이상을 꼭 지키세요).
   - 나중에 SQL을 다시 Run할 때 `'여기를-바꾸세요'`를 그대로 두면, 기존 비밀번호가 그대로 유지돼요.
   - `supabase.sql`이 바뀌면(기능 추가 등) 통째로 다시 Run하면 돼요. 여러 번 Run해도 안전하고, 명단, 뽑은 팀, 고른 메뉴, 객실, 자유시간, 점심은 그대로 남아요. 있던 함수의 이름과 인자는 그대로라 예전 화면과도 맞아요.
   - Run 결과에 `WARNING: anon 의 제한 시간을 바꾸지 못했어요`가 없어야 해요. 이 SQL은 참가자(anon)의 DB 제한 시간을 3초에서 8초로 늘려요. 못 바뀌어도 3초 기본값으로 동작해요. 확인은 SQL Editor에서 `select rolconfig from pg_roles where rolname = 'anon';` → `{statement_timeout=8s}`가 나오면 돼요.
   - 탑승 차량 뽑기를 넣을 때도 같아요. **SQL을 먼저 Run**하면 `people`에 `car`·`car_at` 칸이 생기고 `config`에 처음 차량 목록(1호차·2호차, 정원 자동, 운전자·문구 없음)이 들어가요(다시 Run해도 진행자가 고친 목록은 그대로예요). 확인은 `select value from config where key = 'cars';`예요.
   - 화면 파일과 `supabase.sql`이 함께 바뀌었으면 **SQL을 먼저 Run한 뒤** 화면 파일을 올려요. 순서가 바뀌면 그사이 진행자 화면이나 이미 열려 있는 참가자 화면이 잠깐 오류를 낼 수 있어요.
   - **행사 중(뽑기를 하는 동안)에는 SQL과 화면 파일을 바꾸지 마세요.** 꼭 바꿔야 하면 참가자에게 새로고침을 안내해요.
3. 진행자 화면에서 비밀번호를 입력해요. **명단 관리**에 명단을 붙여넣고 **추가**를 눌러요. 두 가지 형식을 쓸 수 있어요.
   - 엑셀에서 **이름·직급·성별·부서** 4칸을 그대로 복사해 붙여넣기 (머리글 줄은 자동으로 건너뛰어요)
   - 한 줄에 **이름, 부서** (직급·성별 없이 빠르게 추가할 때)
   - 칸 수가 맞지 않는 줄(예: 번호 칸이 더 있는 5칸)은 넣지 않고 입력칸에 남겨 둬요. 고쳐서 다시 **추가**를 누르면 돼요.
   - 4칸인데 셋째 칸이 성별(남·여·빈칸)이 아니면 칸 순서가 다른 것으로 보고 넣지 않아요(예: 이름·부서·직급·성별 순서). 엑셀 칸 순서를 이름·직급·성별·부서로 맞춰 주세요.
   - 머리글 줄(이름·부서, 성명·소속 등)과 칸을 감싼 따옴표는 알아서 건너뛰거나 지워요.
   - 명단을 SQL로 한 번에 넣고 싶으면, 로컬의 `roster-setup.sql`(**명단 등록만** 들어 있어요)을 쓰면 돼요. 먼저 `supabase.sql`을 Run한 뒤 이 파일을 Run해요. 여러 번 Run해도 같은 사람이 두 번 들어가지 않아요. 이 파일은 실명이 들어 있어서 저장소에 올라가지 않아요.
   - 옛 판(설치 SQL 전체)은 `roster-setup.sql.bak-20261119`에 있어요. **이 파일은 Run하면 안 돼요.** 함수가 옛 버전으로 덮어써져요.
   - 줄 끝의 빈 칸(엑셀 빈 열)은 지우고 읽고, 따옴표로 감싼 칸 안의 쉼표는 나누지 않아요. 못 넣은 줄은 "N칸인 줄 M개"처럼 이유를 알려 줘요. 붙여넣은 목록 안에 같은 사람이 있으면 알려 주고 첫 줄만 넣어요.
   - 주의: 부서 칸이 빈 채로 `이름 · 직급 · (빈칸)`만 붙이면 직급이 부서로 읽힐 수 있어요. 넣기 전에 확인하세요.
   - 새 부서(공백만 다른 비슷한 부서 포함)이거나 다른 부서에 같은 이름이 있으면 **추가** 전에 한 번 물어봐요. 붙여넣기 칸 아래에 지금 있는 부서 목록이 보여요.

## 행사 중에

- **진행자 화면의 칸(모두 접고 펴는 칸):** 맨 위 제목·숫자·링크·마지막 갱신 줄·프로젝터 보기 단추와 경고, 그 아래 요약 타일은 늘 보이고, 나머지는 모두 같은 모양의 접고 펴는 칸이에요. 제목 줄(누르면 펴고 접혀요)에 칸마다 핵심 숫자가 있어서 접어 둔 채로도 현황을 볼 수 있어요(5초마다 같이 바뀌어요).
  - **칸 순서:** **한눈에 보기** → 참가자 메인과 같은 순서로 **일정표** → **탑승 차량** → **12/18(금) 아침 메뉴** → **12/18(금) 점심** → **12/18(금) 저녁 자유시간** → 현장에서 발표용 뽑기 화면으로 뽑는 **객실표** → **팀** → 관리용 **명단 관리** → **초기화**(맨 끝). 방·팀 순서는 요약 타일·한눈에 보기 열·분류 단추·엑셀 열과 같아요.
  - **제목 줄 숫자:** 한눈에 보기 `29명`, 일정표 `3일 · 일정 21개`(없으면 `아직 없음`), 탑승 차량 `20/29명 정해짐`(운전자 포함), 아침 메뉴 `12/29명 고름 · 메뉴별 인원`, 점심 `8/29명 고름 · 일반 설렁탕 N · 얼큰 설렁탕 N`, 자유시간 `6/29명 고름 · 스키 N · 휴식 N`, 객실표 `10/29명 배정 · 남자 5실 · 여자 2실`, 팀 `12/29명 뽑음`, 명단 관리 `총 29명`, 초기화 `12/29명 기록 있음`(팀·방·아침 메뉴·점심·자유시간·탑승 차량 손님 중 하나라도 있는 사람). 팀·탑승 차량은 인원이 어긋나면 ` · ⚠ 인원 어긋남`이 붙어요.
  - **열어 둔 칸은 그 브라우저에 기억해요**(새로 고침해도 그대로, 브라우저 저장소 키 `team-picker-board-open`). 처음 들어오면 **한눈에 보기만** 펴져 있어요. 5초 새로고침은 열고 닫은 상태와 입력하던 내용을 건드리지 않아요. 저장소가 막힌 브라우저(일부 사생활 보호 모드)에서는 기억만 못 하고 나머지는 그대로예요.
  - 아침 메뉴·점심·자유시간 칸의 **복사** 단추는 모두 칸 안 아래쪽 도구 줄 오른쪽 끝에 있어요(제목 줄에는 단추가 없어요). "팀을 아직 안 뽑은 사람"과 **늦게 온 사람 빠른 추가**는 **팀** 칸 안(팀 열 아래)에 있어요.
- **한눈에 보기:** 진행자 화면 맨 위(늘 보이는 요약 타일)에 `차량 N/29(운전자 포함) · 아침 메뉴 N/29 · 점심 N/29 · 자유시간 N/29(스키·휴식) · 방 N/29 · 팀 N/29` 숫자가 있고, 그 아래 **한눈에 보기** 칸에 사람마다 **차량·아침 메뉴·점심·자유시간·방·팀**을 한 줄로 보여 주는 표가 있어요(열 순서도 이와 같아요). 아직 안 한 칸은 빨간 **아직**으로 보이고(운전자는 차량 칸에 `1호차 운전`), 머리글을 누르면 그 칸으로 줄을 세워요(한 번 더 누르면 거꾸로 — '아직'이 위로. 차량은 차량 목록 순서). 차량은 탑승 차량 칸이 따로 받아 오는 자료라, 아직 못 받았거나 받기에 실패했으면 차량 칸과 타일은 `-`로 보이고 나머지 표는 그대로예요. 휴대폰(700px 이하)에서는 표 글자를 11px로 줄이고 칸 여백을 좁혀, 칸 안의 글을 띄어쓰기 자리에서 줄바꿈해(예: 아침 메뉴 "버섯 황태 해장국"은 세 줄) **옆으로 밀지 않고도 여덟 열이 모두** 보여요(열이나 정보를 줄이지 않아요. 넓은 화면의 모양은 그대로예요). 프로젝터 보기에서는 숨겨져요.
- **맨 위 숫자·링크:** 제목 옆 숫자는 `전체 29명 · 팀 뽑음 N명 · 팀 남음 N명`(팀 기준)이고, 그 옆 **발표용 뽑기 화면(팀·방)** 단추가 `draw.html`로 가요. 같은 단추가 팀 칸 맨 위의 안내 줄("팀은 참가자가 직접 뽑지 않고 현장에서 발표용 뽑기 화면으로 뽑아요")과 객실표 칸에도 있어요. **프로젝터 보기** 단추 아래에는 "발표용 뽑기 화면으로 뽑는 중이면 이 화면을 프로젝터에 띄우지 마세요. 결과가 미리 보여요." 경고가 항상 보여요.
- **마감 안내(아침 메뉴·점심·자유시간·탑승 차량 칸):** 네 칸 모두 제목 바로 아래에 같은 틀로 있어요. 마감(11/25(수) 15시) 전에는 "참가자는 11/25(수) 15시까지 …할 수 있어요. 그 뒤로는 여기서만 바꿀 수 있어요. (방법: …)", **마감이 지나면 "마감됐어요(11/25(수) 15시). 지금은 여기서만 바꿀 수 있어요. (방법: …)"**로 바뀌어요. 화면을 열어 둔 채 마감 시각을 넘겨도 1초 안에 저절로 바뀌어요(칸의 열림·입력하던 내용은 그대로). 마감 시각은 `common.js` 의 `CHOICE_DEADLINE` 이에요. 방법은 칸마다 달라요: 아침 메뉴는 명단 관리의 **수정**, 점심·자유시간은 **직접 고치기**, 탑승 차량은 **직접 옮기기**예요.
- **진행자 화면:** 5초마다 저절로 새로고침돼요. 방금 뽑힌 사람은 1분 동안 굵은 테두리와 **방금** 표시가 붙어요(움직임 줄이기 설정에서도 보여요).
- **프로젝터 보기:** 진행자 화면 위쪽 **프로젝터 보기** 단추(또는 주소 끝에 `?tv=1`)로 켜요. 되돌릴 때는 **관리자 페이지로**를 눌러요. 제목은 평소 **관리자 페이지**, 프로젝터 보기에서는 **팀 현황**으로 보여요.
  - 큰 글씨, 팀 인원 큰 숫자로 보이고 팀 열은 부서·이름순이에요. 관리용 칸은 숨기고, 화면이 꺼지지 않게 해요(지원하는 브라우저에서).
  - 차량은 보여 주지 않으므로 프로젝터 보기에서는 차량 자료(`board_cars`) 5초 받기를 쉬어요. **관리자 페이지로**를 누르면 곧바로(5초를 기다리지 않고) 다시 받아요.
  - 접고 펴는 칸으로 바꾼 뒤에도 예전처럼 **팀 열 → 팀을 아직 안 뽑은 사람 → 아침 메뉴**가 늘 펼쳐진 채로 나와요(접을 수 없고, 이때 펼친 것은 기억하지 않아요).
  - "마지막 갱신" 시각이 보여요. 30초 넘게 못 받으면 경고가 떠요.
- **팀 인원 목표·경고:** 팀 열 머리에 "목표 7~8명"처럼 보여요. 어떤 팀이 목표를 넘거나, 다 뽑았는데 팀 인원 차이가 2명 이상이면 팀 칸 맨 위에 경고가 뜨고, 접어 둔 팀 칸 제목 줄에도 `⚠ 인원 어긋남`이 붙어요. 위 ⚠️ 안내처럼 안 온 사람을 지우고, 많은 팀의 한 명을 **다시 뽑기** 하라는 뜻이에요.
- **이름 누르기 메뉴:** 팀 칸의 "팀을 아직 안 뽑은 사람"의 이름을 누르면 작은 메뉴가 떠요: **팀 대신 정하기 · 수정 · 삭제**. 팀 열의 이름을 누르면 **다시 뽑기 · 수정**이에요(휴대폰에서는 화면 아래 판으로 떠요).
  - **팀 대신 정하기:** 팀은 원래 현장에서 발표용 뽑기 화면으로 뽑아요. 그 자리에 없거나 따로 정해야 하는 사람의 팀만 진행자가 여기서 대신 정해요(누르면 그 사람의 팀이 바로 무작위로 정해져요). 아침 메뉴는 안 골라도 되고, 같이 정하려면 메뉴도 골라요. 명단 표에서 팀 없는 줄에도 **팀 대신 정하기** 단추가 있어요.
- **늦게 온 사람 빠른 추가:** 팀 칸 안("팀을 아직 안 뽑은 사람" 아래)의 한 줄 칸에 "이름, 부서"를 적고 **추가**를 눌러요. 명단에 없는 부서나 공백만 다른 비슷한 부서면 한 번 확인해요. 같은 이름·부서가 이미 있는 등 추가하지 못한 이유는 맨 위가 아니라 **입력칸 바로 아래** 빨간 글로 나와요(성공 문구도 같은 자리).
- **명단 관리에서 사람 찾기:** 진행자 화면 아래쪽(초기화 칸 바로 위) **명단 관리**를 열어요. 제목 줄에 총인원이 나와요.
  - **분류 단추:** 부서·성별·구분(임원/직원)·직급·**차량·아침 메뉴·점심·자유시간·방**·팀마다 인원수가 적힌 단추가 있어요(예: `점심 안 고름 21`). 누르면 표에 그 사람들만 보이고, 한 번 더 누르면 풀려요. 여러 분류를 함께 고를 수 있어요(예: 기술부 + 아침 메뉴 안 고름). 차량 단추는 탑승 차량 자료를 받은 뒤에 생겨요(운전자는 운전하는 차량에 세어요).
  - **찾기 칸:** 이름·부서·직급으로 찾아요. 띄어쓰기는 무시해요.
  - **정렬:** 표 머리글(부서·이름·직급·성별·팀·아침 메뉴)을 누르면 그 칸 순서로 줄을 세워요. 한 번 더 누르면 거꾸로예요. 직급은 높은 순이에요.
  - **엑셀 파일로 받기:** 지금 표에 보이는 사람들을 엑셀에서 열리는 파일(CSV)로 내려받아요. 열은 `부서·이름·직급·성별·구분·탑승 차량·아침 메뉴·점심·자유시간·객실·팀`이에요(명단 전체 삭제 전의 백업 파일과 같은 열). 받기 직전에 탑승 차량 정보를 새로 받고, 못 받으면 차량 칸을 비우고 그렇다고 알려 줘요. 이 파일을 다시 읽어 들이는 기능은 없어요. 예: 아침 메뉴 하나를 누른 뒤 받으면 그 메뉴를 고른 사람 명단이 돼요. 받은 파일에는 실명이 들어 있으니 저장소에 올리지 마세요.
  - 직급 정렬 순서에 팀장·실장·수석·책임·선임 등 흔한 직급을 넣어 두었어요. 목록에 없는 직급은 "순서를 모르는 직급: …"으로 알려 줘요.
  - 분류·찾기·정렬은 보는 방법만 바꿔요. 명단 자체는 바뀌지 않고, 화면을 새로고침하면 처음으로 돌아가요.
- **명단에 없다고 나오는 사람:** 진행자 화면의 명단 관리에서 바로 추가하면 돼요(표 아래 **명단 추가**).
- **이름·부서·직급·성별이 틀린 사람:** 명단 표에서 **수정**을 누르면 그 줄이 입력칸으로 바뀌어요. 고친 뒤 **저장**(또는 Enter)을 누르면 돼요. Esc는 취소예요.
  - 이미 뽑은 사람을 고쳐도 팀은 그대로예요.
  - 같은 부서에 같은 이름이 이미 있으면 저장되지 않아요. 부서를 바꿀 때 새 부서이거나 다른 부서에 같은 이름이 있으면 한 번 물어봐요.
  - 한 사람을 수정하는 중에도 표의 다른 줄은 계속 새로 받아요. 다른 줄의 다시 뽑기·삭제를 해도 수정 줄은 열려 있어요. 수정 중인 사람이 다른 곳에서 지워지면 줄이 닫히고 알려 줘요.
- **잘못 뽑힌 사람:** 명단 표에서 **다시 뽑기**를 누르면 그 사람의 팀이 비워져요(참가자는 팀을 직접 뽑지 않아요). 비운 팀은 현장에서 **발표용 뽑기 화면**(`draw.html`)의 **그대로 두고 남은 사람만 뽑기**로 다시 뽑거나, 이 화면에서 **팀 대신 정하기**로 넣어요. 한 사람 **다시 뽑기**는 팀만 지우고 아침 메뉴는 그대로 둬요. 모두 뽑은 뒤에 한 사람만 다시 뽑으면, 인원을 맞추려고 대개 같은 팀이 다시 나와요.
- **처음부터 다시 하기(초기화):** 진행자 화면 맨 아래 **초기화** 칸(눌러서 펼침)에 단추가 한곳에 모여 있어요. 참가자가 뽑거나 고른 결과만 지우고, **명단·일정표·차량 목록(운전자 지정 포함)·관리자 비밀번호는 그대로** 남아요.
  - **전체 초기화:** 팀·방·아침 메뉴·점심·자유시간·**탑승 차량**을 한 번에 **모두** 비워요.
  - **항목별 초기화:** **팀 초기화**, **방 초기화**, **아침 메뉴 초기화**, **점심 초기화**, **자유시간 초기화**, **탑승 차량 초기화** — 누른 항목만 비우고 다른 항목은 그대로예요. 팀 초기화는 팀만 지우고 아침 메뉴는 그대로, 탑승 차량 초기화는 손님만 비우고 운전자 지정은 그대로예요. 아침 메뉴 초기화는 DB 함수 `admin_clear('menu')` 한 번으로 지워서, 누르는 순간 참가자가 고른 메뉴가 남는 일이 없어요(DB가 예전 판이면 예전 방식으로 대신 해요). (예전의 **전체 다시 뽑기**(팀·조식)는 **팀 초기화** + **아침 메뉴 초기화**로 같은 일을 해요. 각 칸에 있던 **객실 모두 비우기**·**고른 것 모두 지우기**·**차량 모두 비우기**도 이 칸으로 옮겼어요.)
  - **확인은 한 번:** 누르면 `전체 초기화: 팀 12명 · 방 10명 · 아침 메뉴 12명 · 점심 8명 · 자유시간 6명 · 탑승 차량 5명의 기록을 지울까요?`처럼 무엇이 몇 명분 지워지는지 한 줄로 보여 주고, **확인**을 누르면 바로 지워요(**취소**하면 아무것도 안 지워요). 글자를 적거나 백업 파일을 받는 단계는 없어요. 지우기 전에 남겨 두고 싶으면 먼저 아침 메뉴·점심 칸의 **복사**, 탑승 차량 칸의 **차량별 탑승자 복사**, 명단 관리의 **보이는 명단을 엑셀 파일로 받기**(차량·아침 메뉴·점심·자유시간·객실·팀 칸까지)를 써요. 잘못 지웠으면 아래 **실수로 지웠을 때**의 SQL로 되살릴 수 있어요.
  - **마감(11/25(수) 15시) 뒤에 초기화하면** 확인 문구에 "⚠️ 마감이 지나 참가자가 다시 고르거나 뽑을 수 없어요(…). 지운 뒤에는 진행자가 직접 넣어야 해요."가 나와요(아침 메뉴·점심·자유시간·탑승 차량). 마감 전에는 "마감 전까지 참가자가 다시 고르거나 뽑을 수 있어요."가 나와요. 팀·방은 마감과 상관없이 발표용 뽑기 화면이나 진행자 화면에서 다시 정해요.
  - **전체 초기화가 중간에 실패하면**(인터넷이 끊기는 등) "비운 것: … / 아직 남은 것: …"을 알려 줘요. **다시 누르면** 이어서 지워요(이미 빈 것은 그냥 지나가요).
  - **명단 전체 삭제**(명단 관리 맨 아래)는 초기화가 아니라 명단 자체를 지우는 일이라 예전 그대로예요: "삭제"를 직접 적고 → 그때의 명단 전체를 `워크숍_백업_…csv` 파일로 받고 → **백업 파일이 받아졌는지 확인하는 상자**에서 **파일을 확인했어요. 실행하기**를 눌러야 지워져요.
- **자동 섞기(팀·방·탑승 차량):** 뽑는 항목 세 가지는 진행자가 한꺼번에 정할 수 있어요. 단추는 **팀** 칸·**객실표** 칸·**탑승 차량** 칸 안 맨 아래 도구 줄의 **맨 앞**에 같은 이름으로 두 개씩 있어요(칸을 보다가 바로 누를 수 있게. 초기화 칸에는 없어요).
  - **○○ 자동 섞기 · 안 뽑은 사람만**(`팀 자동 섞기 · 안 뽑은 사람만`, `방 …`, `탑승 차량 …`): 이미 정해진 사람은 **그대로** 두고 **안 정해진 사람만** 정해요. 확인 상자에 `안 뽑은 17명을 자동으로 넣을까요?`처럼 몇 명이 대상인지 나와요. 넣을 사람이 없으면 확인 없이 "넣을 사람이 없어요"만 알려 줘요.
  - **○○ 전부 새로 섞기**(`팀 전부 새로 섞기`, `방 …`, `탑승 차량 …`): 그 항목을 **모두 비우고 전원을 새로** 정해요. 확인 상자에 `지금 12명의 팀 기록(발표용 뽑기 화면에서 뽑은 팀 포함)을 지우고 전원(29명)을 새로 정해요. 되돌릴 수 없어요.`처럼 나와요. 탑승 차량은 **운전자 지정·차량 목록은 그대로**예요.
  - 규칙은 참가자·발표용 화면의 뽑기와 **똑같아요**(DB 함수 `admin_shuffle` 이 `pick`·`pick_room`·차량 뽑기를 그대로 써요): 팀은 팀 인원·임원·부서·남녀를 고르게, 방은 남녀 따로·인원은 고르게·나머지는 무작위, 차량은 운전자를 빼고 차량마다 고르게·나머지는 무작위.

  - 칸의 **복사** 단추를 누르면 `12/18(금) 조식: 우거지 해장국 10 · … (아직 안 고름 2) / 총 29명` 같은 한 줄이 복사돼요(주방 전달용이라 식당과 쓰는 말 "조식"을 그대로 둬요). 복사가 막히면 글 상자로 보여 줘요.
- **메뉴를 잘못 고른 사람:** 참가자는 11월 25일(수) 15시까지 스스로 바꿀 수 있고, 마감 뒤에는 진행자만 바꿀 수 있어요(마감 뒤에도 계속 돼요). 명단 표에서 **수정**을 누르고 아침 메뉴 칸을 바꾼 뒤 **저장**하면 돼요. `-`로 두고 저장하면 그 사람이 메뉴를 다시 고를 수 있어요(마감 뒤에는 고르지 못해요). **팀 대신 정하기**에서 메뉴를 같이 정하는 것도 마감 뒤에 돼요(`admin_assign` 의 `menu`).
- **마감 시각 바꾸기:** 점심·아침 메뉴·자유시간·**탑승 차량 뽑기**의 마감은 **2026-11-25(수) 15:00 한국 시간**이에요. 바꾸려면 두 곳을 **함께** 고쳐요. ① `supabase.sql` 의 `choices_closed()` 안 시각(`timestamptz '2026-11-25 15:00:00+09'`) ② `common.js` 의 `CHOICE_DEADLINE`(`Date.parse('2026-11-25T15:00:00+09:00')`)과 화면에 보이는 글 `CHOICE_DEADLINE_LABEL`('11월 25일(수) 15시'), `CHOICE_DEADLINE_SHORT`('11/25(수) 15시'). `supabase.sql` 의 오류 문구(`choose_lunch`·`choose_menu`·`choose_activity`·`pick_car` 네 함수. 앞의 셋은 '…11월 25일(수) 15시까지만 고르고 바꿀 수 있어요…', `pick_car` 는 '탑승 차량 뽑기는 11월 25일(수) 15시에 마감됐어요…'. 화면은 `common.js` 의 `CHOICE_CLOSED_ERR` 로 이 두 꼴을 마감 거절로 알아봐요)와 진행자 화면(`board.html`)의 안내 글도 같이 맞춰요. 고친 뒤 SQL을 다시 Run하고(안전해요), 세 HTML(`index.html`·`board.html`·`draw.html`)의 `common.js?v=숫자`를 올려요. 실제로 막는 쪽은 서버이고 화면은 그에 맞추는 용도예요. 휴대폰 시계가 늦어 아직 열려 보여도 서버가 마감이라고 거절하면 화면이 마감 모습으로 바뀌어요.
- **점심 고치기(진행자):** 진행자 화면의 **12/18(금) 점심** 칸과 한눈에 보기의 점심 열에서 보고 고쳐요(마감 뒤에도 돼요). 서버 쪽은 `admin_assign` 의 `lunch`(`plain` 일반·`spicy` 얼큰, 빈 문자열이면 비움)와 `admin_clear` 의 `lunch`(맨 아래 초기화 칸의 **점심 초기화**와 **전체 초기화**가 씀)예요.
- **방·팀 뽑기 숨기기:** 지금 참가자 메인에서는 방 뽑기·팀 뽑기 버튼이 숨겨져 있어요(`index.html` 맨 위 script 의 `const HIDDEN_TASKS = new Set(['Room', 'Team'])`). 다시 보이게 하려면 여기서 `'Room'`(방) 또는 `'Team'`(팀)을 빼고 올려요. 숨기는 동안은 '남은 것'·진행 막대에서도 빠지고, 같은 방·우리 팀 사람도 받아 오지 않아요. 화면과 DB 함수는 그대로 있어요.

## 일정표

진행자 화면의 **일정표** 칸에 적은 글이 참가자 화면에 그대로 나와요(메인 화면의 **📅 17~19일 일정 한눈에 보기**).

- **적는 법:** **일정 고치기**를 눌러 글로 적어요. 날짜는 한 줄에 따로 적고, 일정은 `10:00 도착`이나 `14:00~16:00 팀 게임`처럼 시간으로 시작하는 한 줄로 적어요. 시간 사이에는 `~`, `-`, `–`, `—`, `∼`, `～`를 쓸 수 있어요. **예시 넣기**를 누르면 12/17(목)~12/19(토) 2박 3일 예시가 들어가요.
  - 날짜 줄을 `Day 1 · 12/17(목) — 화합과 소통`처럼 적으면 꼬리표(Day 1)·날짜·주제로 나눠 보여줘요.
  - 내용에 든 낱말(식사·강의·특강·레크리에이션·이동·출발·자유 시간·사진 등)에 맞춰 그림 표시가 붙고, 강의·세션은 굵게 나와요.
  - `오프닝 : 대표 인사, 일정 안내`처럼 쌍점(앞뒤를 띄운 `:`) 뒤에 적은 설명은 작은 글로 아래에 나와요.
  - 일정이 이미 있는 날짜 아래에 **시간 없이 적은 줄**(예: `※ 우천 시 실내 진행`)은 바로 앞 일정의 작은 설명으로 붙어요. `12/18(금)`, `12월 18일`, `Day 2`처럼 날짜 모양의 줄만 새 날짜 제목이 돼요.
- **적는 동안:** 아래에 참가자 화면과 같은 **미리보기**와 "날짜 제목으로 읽힌 줄" 목록이 나와요. 의도하지 않은 줄이 제목이 됐는지 확인하세요. `N / 4000자`가 표시되고, 넘으면 저장되지 않아요. 빈 내용으로 저장하려고 하면 한 번 더 물어봐요.
- 저장하면 바로 바뀌어요. 참가자가 열어 둔 메인·일정표 화면은 30초 안에 저절로 새 일정으로 바뀌어요. 고치기 전의 글은 DB에 남아요(아래 **실수로 지웠을 때**).
- 참가자 화면: 행사 날이면 오늘 날짜만 펼쳐지고, 지금 일정에 **지금**(없으면 다음 일정에 **다음**) 표시가 붙어요. 참가자가 직접 접고 편 상태는 자동으로 새로 받아도 그대로예요.
- 적어 둔 일정이 없으면 참가자 화면에는 "아직 일정표가 준비되지 않았어요."라고 나와요.

## 객실·자유시간

진행자 화면의 **12/18(금) 저녁 자유시간** 칸(점심 칸 아래)과 **객실표** 칸(자유시간 칸 아래, 팀 칸 위)이에요.

- **객실표:** 방은 남자 1~5호실, 여자 1~2호실로 7개예요. 방은 참가자가 뽑지 않고 현장에서 진행자가 **발표용 뽑기 화면**(`draw.html`, 칸 안의 단추로도 가요)으로 뽑아요(남녀 따로, 인원은 고르게, 나머지는 무작위). 여기서는 그 결과를 확인하고 직접 고쳐요. 방을 비우면 발표용 화면에서 다시 뽑아요.
  - 한 사람의 방을 다시 정하려면 **직접 옮기기**를 켜고 그 사람의 방을 '방 없음'으로 바꾸거나(발표용 화면에서 다시 뽑아요) 다른 방으로 바로 옮겨요.
  - 방이 없는 사람은 **방 자동 섞기 · 안 뽑은 사람만**으로 채워요(예전 이름 **방 없는 사람만 넣기**). 이미 방이 있는 사람은 그대로 두고, 남은 사람을 발표용 화면의 방 뽑기와 같은 규칙으로 넣어요(인원이 적은 방부터, 방 인원 차이는 가능한 한 1명 이내).
  - **방 전부 새로 섞기**(예전 이름 **자동으로 나누기**)는 이미 뽑은 방까지 **모두 비우고 전원을 새로** 나눠요(남녀 따로, 인원은 고르게, 나머지는 무작위 — 발표용 뽑기 화면의 방 뽑기와 같은 기준). 발표용 화면을 쓰지 않고 진행자가 한꺼번에 정할 때만 쓰세요. 두 단추 모두 아래 **자동 섞기**에서 자세히 설명해요.
  - 모든 방을 비우려면 맨 아래 초기화 칸의 **방 초기화**를 눌러요. 발표용 화면에서 뽑은 방까지 지워서 모두 다시 정해야 해요.
  - 성별이 없는 사람은 방을 뽑을 수도, 자동 섞기로 정할 수도 없어요(자동 섞기는 그 사람을 이름·부서와 함께 "성별이 없어서 방을 못 정했어요"로 알려 줘요). 명단 관리에서 성별을 넣거나 **직접 옮기기**로 넣어요.
- **12/18(금) 저녁 식사 뒤 자유시간:** 참가자가 메인의 **⛷️ 자유시간** 버튼에서 **스키**와 **휴식** 중 직접 골라요. 11월 25일(수) 15시까지 다시 눌러 바꿀 수 있고, 그 시각부터는 진행자만 바꿀 수 있어요.
  - 진행자 화면에 스키·휴식 인원과 이름, 아직 안 고른 사람이 나와요. 스키를 고른 사람은 **18일 저녁 식사 때 술 금지** 안내를 받고 약속한 사람이에요. **직접 고치기**를 켜면 진행자가 대신 바꿀 수 있어요.
  - 예전의 '사우나'는 없어졌어요. SQL을 다시 Run하면 '사우나'로 적혀 있던 사람은 '휴식'으로 바뀌어요.
- 한꺼번에 지우려면 맨 아래 초기화 칸의 **전체 초기화**를, 하나씩 지우려면 같은 칸의 **방 초기화**, **자유시간 초기화** 등을 쓰세요(위 **처음부터 다시 하기(초기화)**).

## 발표용 뽑기 화면

레크리에이션 전에 진행자가 노트북을 프로젝터에 띄워 **팀 뽑기**와 **방 배정 뽑기**를 다 함께 보며 진행하는 화면이에요.

- **주소:** 관리자 페이지 옆의 `draw.html` (https://dydrkflqmdl.github.io/team-picker/draw.html). 관리자 페이지 맨 위 **발표용 뽑기 화면(팀·방)** 링크로도 가요.
- **진행자만:** 관리자 비밀번호를 넣어야 열려요. 같은 기기에서 관리자 페이지에 들어간 적이 있으면(비밀번호가 저장돼 있으면) 묻지 않아요. 관리자 페이지의 **이 기기에서 비밀번호 지우기**를 누르면 이 화면도 다시 물어요.
- **첫 화면:** **① 레크리에이션 팀 뽑기**와 **② 방 배정 뽑기** 중 골라요(키보드 `1`·`2`도 돼요). 팀 결과 화면에 **② 방 배정 뽑기로 →**가 있어 차례로 이어 갈 수 있어요.
- **진행(기본: 전체 한 번에):** 시작 화면에서 **시작하기**를 누른 뒤, 뽑는 화면에서 **딱 한 번** 누르면 끝이에요(`스페이스` · `→` · `Enter` · `PageDown`(발표용 무선 리모컨) 또는 화면의 **뽑기 시작 ▶**).
  1. 룰렛이 돌아요. 이름이 섞이며, 그동안 남은 사람 전원의 팀(방)을 한 명씩 DB로 정해 저장해요. 아래 막대에 **정한 인원 / 전체**가 차올라요. 아직 안 정한 사람이 보일 때는 그 사람이 갈 수 있는 칸만 옅게 켜지고, 이미 정해진 사람이 보일 때만 그 사람의 칸이 밝게 켜져요.
  2. 저장이 끝나면 룰렛이 점점 느려지다 멈추고(느려질 때 보이는 이름과 칸은 진짜 결과예요), 모든 칸이 한꺼번에 켜지며 **결과 공개!**가 떠요.
  3. **더 누르지 않아도** 전체 결과 화면으로 넘어가요. 팀 색이 켜지고 이름이 칸마다 채워지며 꽃가루가 내려요. 팀은 4칸, 방은 남자 5칸·여자 2칸이에요. 이름 글자는 칸에 맞춰 가장 크게 보여요.
  - **룰렛 길이:** 저장이 빨리 끝나도 **최소 3.5초**는 돌고, 그다음 1.4초 동안 느려지다 멈춰요(멈춘 뒤 0.7초 뒤 전체 결과). 저장이 오래 걸리면 끝날 때까지 계속 돌며 막대가 차올라요(29명 기준 실제로는 보통 3~9초). 누른 때부터 전체 결과까지 보통 6~11초예요.
  - 룰렛·저장 중에 누른 키는 무시해요(연타해도 한 번만 진행돼요). 뽑는 화면이 열린 직후 **0.6초** 동안의 키도 무시해요(시작 화면에서 `Enter`를 두 번 눌러 곧바로 저장이 시작되지 않게). 전체 결과로 저절로 넘어간 직후 **2.8초** 동안은 그 화면 단추(방 배정 뽑기로·처음 화면으로)를 클릭·키로 누를 수 없어요. 룰렛 중에 누르던 키·클릭이 다음 단계로 넘겨 버리지 않게 하려는 거예요.
  - 전체 결과 화면에서는 진행 키(`스페이스`·`→`·`Enter`·`PageDown`)를 눌러도 아무 일도 안 일어나요. 다음 뽑기·처음 화면은 노트북에서 단추를 눌러요.
  - 무선 리모컨(`PageDown`·`→`)은 **뽑는 화면에서만** 넘어가요. 첫 화면·시작 화면·결과 화면의 단추와 확인 상자는 노트북에서 눌러요.
  - 확인 상자(모두 비우기 등)는 처음에 **취소**에 초점이 있고, 열린 직후 0.5초와 누르고 있는 키, `→`·`PageDown`은 무시해요. 확정은 마우스로 누르거나 Tab으로 확인 단추에 옮겨 눌러요.
  - `F`: 전체 화면 켜고 끄기 · `M`: 소리 켜고 끄기(합성음, **처음엔 꺼져 있어요**) · `Esc`: 확인 상자 닫기
- **다른 공개 방법(필요할 때만):** 첫 화면에는 고르는 칸이 없어요. 주소 끝에 붙여 골라요. 이때는 첫 화면에 **공개 방법: ○○**와 **기본(전체 한 번에)으로 바꾸기** 링크가 보여요. 기본값 자체는 `draw.js` 맨 위 `DRAW_CONFIG.unit`(`'all'`·`'group'`·`'person'`)이에요.
  - `draw.html?unit=group` **한 팀·한 방씩:** 첫 누름에 전원을 저장(룰렛)하고, 누를 때마다 팀 하나(방 하나)씩 공개, 마지막에 한 번 더 누르면 전체 결과예요(누르는 횟수 = 팀(방) 수 + 1). 공개하다 끊기면 같은 브라우저에서 **이어서 공개(○○ 팀부터)**가 나와요. 공개하지 않은 팀(방)을 한꺼번에 보이는 **남은 것 모두 공개**도 있어요.
  - `draw.html?unit=person` **한 명씩:** 누를 때마다 한 사람씩 이름이 섞이다 멈추고 팀·방 돌림판이 돌다 멈춰요(이미 뽑은 사람은 처음부터 옆 결과판에 보여요).
- **배정 규칙은 그대로예요.** 화면이 한 사람씩 참가자 화면과 같은 DB 함수(팀 `pick`, 방 `pick_room`)를 대신 불러요. 참가자가 자기 휴대폰으로 하나씩 누르는 것과 똑같아서 위 **규칙**이 그대로 지켜져요. 화면이 정하는 것은 **다음에 누구를 부를지(부르는 순서)**뿐이고 그건 무작위예요.
- **결과는 DB에 저장돼요.** 룰렛이 도는 동안 전원이 저장되고(한 명씩은 공개할 때마다), 저장된 결과는 관리자 페이지에 바로 보여요.
- ⚠️ **발표하는 동안 관리자 페이지를 프로젝터에 띄우지 마세요.** 관리자 페이지(프로젝터 보기 포함)는 저장되는 즉시 모든 결과를 보여 줘요. 참가자 메인은 지금 방·팀 버튼이 숨겨져 있어 화면에는 결과가 안 나와요(숨김을 풀면 바로 보여요).
- **중간에 끊기면:**
  - 인터넷이 끊기면 룰렛이 멈추고 "같은 사람으로 다시 시도"가 떠요(전체 결과로 넘어가지 않아요). `스페이스`(또는 그 단추)로 같은 사람부터 다시 이어 가요. 이미 저장됐던 사람이면 처음 정해진 팀·방이 그대로 나와요(두 번 뽑히지 않아요). 계속 안 되는 사람은 **이 사람 건너뛰기**로 넘기면 나머지를 마저 저장하고 전체 결과로 가요. 건너뛴 사람은 결과 화면에 **아직 안 뽑은 n명**으로 나오고(이때 제목은 축하 대신 "아직 안 뽑은 사람이 있어요") **남은 n명 이어서 뽑기**로 마저 뽑아요. 마지막 한 명을 건너뛰면 기다리지 않고 바로 결과로 가요.
  - 새로고침하거나 노트북을 다시 켜도 괜찮아요. 결과는 DB에 있어서 바뀌지 않아요.
    - **저장(룰렛) 중에 끊겼으면:** 다시 들어가 **그대로 두고 남은 사람만 뽑기**를 누른 뒤 한 번 누르면 남은 사람만 이어서 저장하고 전체 결과로 가요.
    - **전체 결과가 나온 뒤 새로 고쳤으면:** 같은 탭이면 전체 결과가 그대로 다시 보여요(꽃가루·소리 없이). 그사이 관리자 페이지에서 그 결과를 모두 비웠으면 빈 판 대신 첫 화면이 열려요. **처음 화면으로**를 눌러 나간 뒤에는 첫 화면부터 열려요. 다른 기기·탭에서는 시작 화면의 **전체 결과 보기**로 같은 결과를 봐요.
- **이미 뽑은 사람이 있을 때:** 시작할 때 "이미 n명이 뽑았어요"가 나오고 둘 중 골라요.
  - **그대로 두고 남은 사람만 뽑기:** 남은 사람만 룰렛으로 저장하고, 전체 결과에는 이미 뽑은 사람도 함께 나와요.
  - **모두 비우고 처음부터:** 한 번 더 확인한 뒤 지워요. 팀은 팀만 지우고(아침 메뉴·점심·방·자유시간은 그대로), 방은 방만 지워요(관리자 페이지에서 직접 넣은 방도 함께 지워져요). 관리자 페이지 초기화 칸의 **팀 초기화**·**방 초기화**와 같은 일을 하고, **전체 초기화**(여섯 항목 모두)와는 달라요.
  - **모두 이미 뽑았으면:** 룰렛 없이 **전체 결과 보기**로 결과를 바로 보여 줘요. 다시 뽑으려면 **모두 비우고 처음부터**를 눌러요.
- **방 뽑기와 성별:** 성별이 없는 사람은 방을 뽑을 수 없어서 시작 화면에 "성별이 없어 뽑을 수 없는 n명"과 이름이 나오고 건너뛰어요. 뽑기 전에 관리자 페이지 명단에서 성별을 넣거나, 객실표에서 방을 직접 넣어요.
- **발표 도중 빠진 사람:** 발표하는 사이 관리자 페이지에서 누군가의 팀·방을 비웠거나, 오류로 **이 사람 건너뛰기**를 한 사람은 결과 화면에 **아직 안 뽑은 n명**과 이름으로 나와요. **남은 n명 이어서 뽑기**로 마저 뽑아요.
- **안 온 사람:** 위 **규칙**의 ⚠️처럼 명단에 남아 있으면 그 자리만큼 인원이 어긋날 수 있어요. 발표 전에 관리자 페이지에서 지워 두세요.
- **연습 모드:** 비밀번호 화면이나 첫 화면의 **연습 모드**(또는 주소 `draw.html?practice=1`)로 들어가요. 진행은 실제와 똑같아요(한 번 누르면 룰렛 → 전체 결과, 30명이 3~4초쯤 저장돼요). 누가 봐도 견본인 이름(견본 토끼, 견본 사과 …)으로 연출만 미리 해 봐요. 화면에 노란 **연습** 표시가 크게 붙고, **DB를 전혀 부르지 않아요**(읽기도 저장도 안 해요). 배정도 실제 규칙이 아니라 흉내예요. 새로고침하면 처음으로 돌아가요(결과 화면도 기억하지 않아요). 다른 공개 방법을 연습하려면 `draw.html?practice=1&unit=group`처럼 붙여요.
- **움직임 줄이기:** 기기 설정에서 '동작 줄이기'가 켜져 있으면 룰렛 최소 시간·느려지기·번쩍임·꽃가루·이름 채워지기 없이 저장이 끝나는 대로 바로 전체 결과가 나와요. 누르는 방법은 같아요.
- **바꾸기:** 공개 방법 기본값(`unit`), 룰렛 최소 시간(`rouletteMinMs`)·멈추는 시간(`rouletteLandMs`)·멈춘 뒤 머무는 시간(`allHoldMs`), 결과로 넘어간 직후 단추를 막는 시간(`screenGuardMs.finaleAuto`), 소리 기본값 등은 `draw.js` 맨 위 `DRAW_CONFIG`에서 바꿔요(고치면 `draw.html`의 `draw.js?v=숫자`를 올려요). `common.js`·`style.css`의 `?v=`를 올릴 때는 `draw.html`도 같이 올려요.
- 화면은 16:9에 맞춰 그려서 1920×1080·1280×720 어디서나 같은 모양이에요. 화면이 꺼지지 않게 해요(지원하는 브라우저에서).

## 탑승 차량

차량은 **1호차·2호차** 두 대이고, **참가자 전원을 두 차량에 반씩** 나눠요. 운전자는 차량마다 정해져 있고 **뽑지 않아요.**

### 배포 뒤 처음 한 번: 차량 목록 채우기

SQL을 Run하면 차량 목록은 `1호차`·`2호차`, **정원 자동(반씩), 운전자·문구 없음**으로 들어가요. 저장소에 실제 이름을 남기지 않으려고 운전자와 문구는 비워 두었어요. 뽑기를 열기 전에 아래 순서로 채워요.

1. 명단을 확정해요. **안 오는 사람은 뽑기 전에 명단에서 지워요**(자동 정원이 명단 인원으로 계산돼요. 아래 **인원이 어긋날 수 있는 경우**).
2. 관리자 페이지 → **탑승 차량** → **차량 목록 고치기**를 열어요.
3. 차량마다 **운전자**를 명단에서 골라요(부서 · 이름 목록). 운전자를 고르지 않은 차량은 그림의 운전석에 이름 없이 "운전"만 보이고, 뽑기는 그대로 돼요.
4. **문구**를 적어요(예: `○○님 차량`). 화면에는 "1호차 · ○○님 차량"처럼 이름과 함께 보여요. 비워 두면 이름만 보여요.
5. **정원**은 비워 두면 **자동(반씩)**이에요. 숫자를 넣으면 그 숫자(운전자를 뺀 손님 자리 수)를 따라요.
6. **저장**을 눌러요. 차량 상자에 "운전: 이름(부서)"와 "탄 인원/정원(자동)"이 보이면 끝이에요.

### 참가자 화면

- **🚗 타고 갈 차량 뽑기**(메인 두 번째 버튼)에서 **뽑아봐!**를 누르면 차량 하나가 정해져요. 결과는 메인 버튼에도 차량 이름·문구와 **같은 차 사람**(운전자가 맨 앞, "운전" 표시)으로 보여요.
- **완전 랜덤이에요.** 성별·나이·직급·부서를 **전혀 보지 않고**, 남은 빈자리 하나하나가 **같은 확률**이에요(그래서 차량마다 남은 자리 수에 비례해요).
- 한 사람은 **한 번만** 뽑아요. 이미 차량이 있는 사람이 다시 눌러도 같은 차량이 나와요. 다시 뽑으려면 진행자가 그 사람의 차량을 비워야 해요(마감 전까지).
- **마감:** 점심·아침 메뉴·자유시간과 같은 **11월 25일(수) 15시(한국 시간)**까지 뽑을 수 있어요(서버의 `choices_closed()`, 화면의 `CHOICE_DEADLINE` 을 그대로 써요). 마감 전에는 안 뽑은 사람의 메인 버튼에 "11/25(수) 15시까지"가 보여요.
  - **마감 뒤 안 뽑은 사람:** 메인 버튼이 회색 "⏰ 마감됐어요 · 진행자에게 말해 주세요"로 바뀌고 눌리지 않아요('남은 것'에도 세지 않아요). 차량 화면을 열어 둔 채 마감을 넘기면 뽑기 단추가 사라지고 "⏰ 마감돼서 아직 못 뽑았어요."가 보여요. 휴대폰 시계가 늦어 뽑기를 눌러도 서버가 "탑승 차량 뽑기는 11월 25일(수) 15시에 마감됐어요. 차량은 진행자에게 말해 주세요."로 거절하고 화면이 마감 모습으로 바뀌어요. 기준은 다른 고르기(choose_lunch 등)와 같은 **누른 시각**이에요. 그래서 마감 직전에 눌러 차례를 기다린 사람은 차례가 마감 뒤에 와도 받아들여져요.
  - **마감 뒤 이미 뽑은 사람·운전자:** 자기 차량, 같은 차 사람, **그림 보기**를 그대로 써요.
  - **진행자:** 마감 뒤에도 넣기·옮기기·비우기·차량 목록 저장이 다 돼요. 진행자가 넣으면 참가자 화면에는 30초 안에 그 차량이 보여요. 마감 뒤 차량을 비운 사람은 스스로 다시 뽑지 못하니 진행자가 넣어 줘야 해요.
- 뽑은 뒤에도 메인의 차량 버튼("🚗 타고 갈 차량" + **그림 보기** 표시)을 누르면 차량 화면에 다시 들어가, 연출 없이 **지금 그림**(그사이 같은 차에 탄 사람까지)을 볼 수 있어요. 차량 화면은 보고 있는 동안 30초마다 새로 받아요.
- **운전자**가 로그인하면 차량 버튼이 처음부터 끝난 상태(✓)로 "1호차 · ○○님 차량 · 운전"처럼 보이고, 눌러서 들어간 차량 화면에서는 **운전석에 자기 이름**이 "나" 표시와 함께 강조돼요. "남은 것"에서도 차량 뽑기는 끝난 것으로 쳐요. 운전자가 뽑기를 눌러도(직접 불러도) 다른 차량에 배정되지 않아요.
- 여러 명이 동시에 눌러도 DB가 **차량 뽑기끼리만** 한 명씩 차례로 처리하고 정원도 그 차례 안에서 계산해서 **정원을 넘지 않아요.** 팀·방 뽑기와는 서로 기다리지 않아요.
- 자리가 다 차면 "빈자리가 있는 차량이 없어요. 진행자에게 말해 주세요."가 떠요. 자동 정원이면 명단에 사람이 더해질 때 정원이 저절로 늘어나요.
- **차량 그림:** 위에서 본 차 그림이에요.
  - 앞줄 왼쪽 칸은 **운전석**이에요. 운전자가 정해져 있으면 "운전"과 운전자 이름(다섯 글자 이름까지는 그대로 들어가고, 더 길면 줄여요. 전체 이름은 아래 **같은 차 사람들** 목록에 있어요)이, 아니면 "운전"만 보여요.
  - 나머지 좌석은 **지금 정원 수만큼** 그려져요(자동이면 계산된 정원, 15~16명이어도 한 줄에 3칸씩 늘어나요). 탄 사람은 **탄 차례대로** 조수석 → 뒷줄 왼쪽부터 앉고, 빈자리는 점선 "빈자리"예요. **나**는 보라색 테두리와 "나" 표시로 강조돼요.
  - 차량 색은 차량 목록 순서대로 정해져요. 정원보다 많이 타 있으면(명단에서 사람이 지워진 경우 등) 탄 사람 수만큼 좌석을 그려요.

### 정원 자동(반씩) 계산

정원을 비워 둔 차량은 뽑을 때마다, 그때의 명단으로 다시 계산해요(그래서 명단이 바뀌면 다음 뽑기부터 저절로 맞아요).

- **N** = 명단 인원 − 운전자 수(명단에 실제로 있는 운전자만), **F** = 정원을 숫자로 적은 차량들의 정원 합, **A** = 자동 차량 수
- 자동 차량 하나의 정원 = **올림((N − F) ÷ A)** (N − F 가 0보다 작으면 0). 숫자를 적은 차량은 그 숫자 그대로예요.
- 두 대 모두 자동이면 정원이 각각 **올림(N ÷ 2)**이에요. 예: 명단 31명(운전자 2) → 손님 29명 → 정원 15·15.
- ⚠️ **자동 정원 차량이 3대 이상이면 고르게(차이 1명 이내) 나뉜다는 보장이 없어요.** 정원이 각 올림(N ÷ A)이라 남는 빈자리가 2개 이상 생길 수 있고, 그 빈자리가 한 차량에 몰릴 수 있어요. 예: 자동 3대·손님 10명 → 정원 4·4·4(합 12) → 모두 뽑으면 4·3·3 일 수도, **4·4·2** 일 수도 있어요. 3대 이상이면 다 뽑은 뒤 **직접 옮기기**로 맞추거나, 정원을 숫자로 적어 합이 손님 수와 같게 해 두세요(예: 4·3·3).
- **왜 이렇게 하나요:** 빈자리마다 같은 확률로 고르면 "자리 순서를 무작위로 섞어 앞에서부터 앉히는 것"과 같아서, **누구나 뽑는 차례와 상관없이 각 차량에 1/2 확률**이에요. 정원이 각 올림(N ÷ 2)이라 **모두 뽑으면 차이는 1명 이내**이고, 손님이 홀수면 남는 빈자리 하나가 무작위 차량에 생겨서 **1명 많은 차량도 1호차·2호차가 반반**이에요. 정원 계산과 배정을 한 명씩 차례로 하므로 **동시에 뽑아도 반을 넘겨 한쪽에 몰리지 않아요.**
- 로컬 시험 결과예요(`tests/car_db_test.sh`).
  - 운전자 2 + 손님 28명 전원 뽑기 300번: 모두 14·14. 운전자 2 + 손님 29명 전원 뽑기 1000번: 모두 15·14 또는 14·15(1호차가 많았던 비율 50.5~52.1%).
  - 한 사람이 첫 번째로 뽑을 때·마지막(30명 뒤)으로 뽑을 때 각 2000번: 1호차 47~52%(카이제곱 기준 쏠림 없음).
  - 31명이 동시에 눌러도 손님 29명 모두 배정, 차이 1명 이내, 정원 초과 0(경쟁 구간 약 35~40ms).
  - 정원을 적은 4대(합 25)에 40명(운전자 2 포함)이 동시에 눌렀을 때: 손님 25명 배정·정원 초과 0, 운전자 2명은 자기 차량.

### 인원이 어긋날 수 있는 경우

- **끝까지 안 뽑는 사람이 있으면** 그만큼 어긋날 수 있어요. 정원은 명단 전원이 뽑는다고 보고 계산하기 때문이에요.
  - 손님 29명(정원 15·15)에서 1명이 안 뽑으면 28명이 **15·13**이 될 수 있어요(14·14일 수도 있어요). 2명이 안 뽑으면 최대 15·12.
  - 손님 28명(정원 14·14)에서 1명이 안 뽑으면 14·13(차이 1, 평소와 같음), 2명이 안 뽑으면 최대 14·12.
  - 정리하면 차이는 최대 **"안 뽑은 사람 수 + (손님이 홀수면 1)"**이에요.
- **뽑는 도중 명단에서 사람을 지우면:** 정원이 줄어 다시 계산돼요. 이미 한 차량에 새 정원보다 많이 타 있으면 그 차량은 더 뽑히지 않을 뿐 오류는 나지 않고, 그만큼 어긋나요. 예: 손님 28명(정원 14·14)에서 1호차 14명·2호차 2명이 탄 뒤 안 뽑은 4명을 지우면 정원이 12·12가 되고, 남은 8명이 모두 2호차로 가서 **14·10**이 돼요. 반대로 그때 어느 차량도 새 정원보다 많이 타 있지 않으면(예: 10명만 뽑은 뒤 4명을 지움) 끝나면 12·12로 맞아요.
- **뽑는 도중 사람을 더하면** 정원이 늘어나서 끝나면 차이 1명 이내로 맞아요.
- **뽑은 뒤 명단에서 사람을 지우면:** 그 사람이 탄 차량만 1명 줄어요. 한 차량에서 여러 명을 지우면 차이가 **2명 이상**이 될 수 있어요(예: 14·14 에서 1호차 손님 2명을 지우면 12·14).
- **뽑는 동안 명단을 지우지 마세요** — 지우기와 뽑기가 같은 순간에 겹치면 1~2명 어긋날 수 있고, 그때는 아래 **직접 옮기기**로 맞춰요.
- 관리자 페이지 **탑승 차량** 칸은 정원보다 많이 탄 차량이 있거나, 모두 정해졌는데 자동 정원 차량끼리 차이가 2명 이상이면 팀 칸의 인원 경고와 같은 빨간 테두리 상자로 "탑승 인원이 어긋났어요…"를 보여 줘요(지금 인원·정원 함께).
- **맞추는 법(지우거나 안 뽑아서 어긋났을 때 모두):** 관리자 페이지 **탑승 차량 → 직접 옮기기**를 켜고, 인원이 많은 차량의 한 사람 옆 고르는 칸에서 적은 차량을 골라 옮겨요. 차이가 1명 이내가 될 때까지 한 명씩 되풀이해요. 정원 안에서만 옮겨지므로(꽉 찬 차량으로는 "그 차량은 자리가 다 찼어요(정원 N명)."), 받는 쪽은 늘 인원이 적은 차량이에요. 안 오는 사람은 **뽑기 전에** 명단에서 지우는 게 가장 좋아요.
- **마감까지 안 뽑은 사람:** 11월 25일(수) 15시 뒤에는 참가자가 직접 뽑지 못하므로, 진행자가 **탑승 차량 → 직접 옮기기**를 켜고 **아직 안 뽑은 사람**의 고르는 칸에서 차량을 골라 넣어요. 두 차량 인원을 맞추려면 차량 상자 머리의 "탄 인원/정원"을 보고 **인원이 적은 차량부터** 한 명씩 넣어요. 자동 정원(각 올림(손님 수 ÷ 2)) 안에서만 넣어지므로 다 넣으면 차이는 1명 이내예요. 꽉 찬 차량에 넣으려 하면 "그 차량은 자리가 다 찼어요(정원 N명)."가 떠요.

### 운전자

- 운전자는 차량 목록의 **운전자** 칸에서 명단의 사람을 골라 정해요. 그 사람은 **정원에 들지 않고**, 뽑지 않아도 그 차량에 타요(DB에서는 그 사람의 `people.car`는 비워 두고 차량 목록에만 적어요. 그래서 탄 인원·정원 계산·탑승 차량 초기화는 손님만 다뤄요).
- 운전자도 명단에 있으니 방·팀·아침 메뉴·자유시간은 평소처럼 해요. 명단에서 지우지 마세요.
- 한 사람은 한 차량만 운전할 수 있어요("한 사람이 "1호차"·"2호차" 두 차량의 운전자예요. 한 차량에만 골라 주세요.").
- 이미 손님으로 타 있는 사람을 운전자로 고르면 저장이 거절돼요("○○ 님이 이미 1호차에 손님으로 타 있어요. 먼저 비워 주세요."). **직접 옮기기**에서 그 사람의 차량을 비운 뒤 다시 저장해요.
- 운전자를 손님으로 넣을 수는 없어요("운전자는 차량 목록 고치기에서 바꿔요.").
- 운전자를 명단에서 지우면 그 차량은 운전자 없음으로 보이고 뽑기는 그대로 돼요. 관리자 페이지에는 "운전: 명단에 없는 사람(지워짐)"이 보이고, 차량 목록 고치기에서 다른 사람이나 '운전자 없음'으로 바꿔 저장해야 해요(그대로 저장하면 ""1호차" 의 운전자가 명단에 없어요…"로 거절).
- **탑승 차량 초기화**(전체 초기화 포함)는 운전자 지정을 지우지 않아요.

### 관리자 페이지의 "탑승 차량" 칸

진행자 화면 **일정표** 칸 아래, **아침 메뉴** 칸 위의 칸이에요(접어 두어도 제목 줄에 "차량이 정해진 사람(뽑은 손님 + 운전자)/명단 인원 정해짐", 5초마다 맞춰요).
칸 안 맨 위에 다른 마감 칸과 같은 틀로 "참가자는 11/25(수) 15시까지 차량을 뽑을 수 있어요. 그 뒤로는 여기서만 바꿀 수 있어요. (방법: 아래 직접 옮기기를 켜서 인원이 적은 차량에 넣어요.)"가 보여요(날짜는 `common.js` 의 `CHOICE_DEADLINE_SHORT`). 그 아래 한 줄은 "운전자는 뽑지 않고 차량이 정해져 있어요. 나머지 전원은 차량 수대로 반씩 나눠 타요. 마감 전에는 차량을 비우면 그 사람이 다시 뽑을 수 있어요."예요(마감이 지나면 마지막 문장이 "마감이 지나 참가자는 다시 뽑을 수 없어서 진행자가 직접 넣어요."로, 위 마감 안내는 "마감됐어요(11/25(수) 15시). 지금은 여기서만 바꿀 수 있어요. (방법: …)"로 저절로 바뀌어요). 진행자의 넣기·옮기기·비우기·목록 고치기는 마감 뒤에도 다 돼요.

- **차량별 탑승자:** 차량마다 이름·문구, **운전: 이름(부서)** 줄, 탄 손님이 탄 차례대로 번호와 함께 나오고, 머리에 "탄 인원/정원명(자동)"이 보여요. 꽉 찬 차량에는 **꽉 참**이 붙어요. **아직 안 뽑은 사람**은 아래에 따로 나와요(운전자는 여기 없어요).
- **직접 옮기기:** 켜면 사람마다 고르는 칸이 생겨요. 다른 차량을 고르면 옮기고, **차량 비우기(다시 뽑게 하기)**를 고르면 그 사람이 다시 뽑을 수 있어요. **마감(11/25(수) 15시) 뒤에는** 이 항목이 그냥 **차량 비우기**로 바뀌고, 비우면 "마감이 지나 스스로 다시 뽑지 못해요. 여기서 직접 넣어 주세요."가 떠요 — 비운 사람은 진행자가 직접 넣어야 해요. 안 뽑은 사람도 여기서 바로 차량에 넣을 수 있어요. 꽉 찬 차량에는 넣을 수 없어요("그 차량은 자리가 다 찼어요(정원 N명)." — 자동이면 계산된 정원). 운전자는 고르는 칸 대신 **운전자** 표시가 나와요.
- **차량별 탑승자 복사:** `1호차 · ○○님 차량(운전 ○○○ · 13/15): …` 같은 글을 복사해요(운전자가 없으면 `2호차(14/15): …`). 복사가 막히면 글 상자로 보여 줘요.
- **탑승 차량 자동 섞기 · 안 뽑은 사람만 / 탑승 차량 전부 새로 섞기:** 도구 줄 맨 앞의 두 단추(위 **행사 중에**의 **자동 섞기**). 운전자는 빼고, 손님을 차량 뽑기와 같은 규칙으로 정해요. 마감 뒤에도 돼요 — 마감 뒤 안 뽑은 사람이 남았으면 **안 뽑은 사람만**으로 한 번에 넣을 수 있어요(새로 정해진 결과가 최종이에요).
- **모든 손님의 차량 비우기:** 이 칸에는 단추가 없고, 맨 아래 초기화 칸의 **탑승 차량 초기화**(또는 **전체 초기화**)로 해요. 운전자 지정은 그대로예요. 시험으로 뽑은 기록을 지울 때 써요. ⚠️ **마감 뒤에** 누르면 확인 문구에 "마감이 지나 참가자가 다시 고르거나 뽑을 수 없어요(탑승 차량). 지운 뒤에는 진행자가 직접 넣어야 해요."가 나와요 — 마감 뒤에는 쓰지 않는 게 좋아요.
- **차량 목록 고치기:** 차량 목록은 DB `config` 표의 `'cars'` **한 곳**에만 있어요(화면·코드에는 없어요). 줄마다 **이름 · 문구 · 정원(비우면 자동) · 운전자**를 고치고 **차량 더하기**·**빼기**를 한 뒤 **저장**해요.
  - 차량은 1~20대, 이름은 1~30자(서로 달라야 해요), 문구는 0~30자, 정원은 비우거나 1~99명이에요. 정원 칸에 "4명"처럼 숫자가 아닌 글자를 넣으면 저장하지 않고 "정원에는 숫자만 적어 주세요"를 보여 줘요.
  - 운전자 칸은 명단 전원(부서 · 이름)에서 고르고, 손님으로 타 있는 사람에는 "(1호차 손님)"이 붙어 있어요.
  - **탄 사람이 있는 차량은 뺄 수 없고, 저장하면 정원이 지금 탄 인원보다 작아지는 차량이 생기는 목록도 저장되지 않아요.** 정원을 숫자로 적은 경우는 물론, **자동 정원**이 줄어드는 경우도 막아요(운전자를 나중에 지정, 다른 차량에 숫자 정원을 적음, 차량을 더함 — 저장 전에 새 목록으로 뽑기와 같은 계산을 해 봐요). 예: 명단 12명(운전자가 될 2명 포함)에서 1호차에 6명이 탄 뒤 운전자 2명을 지정하면 정원이 5·5 가 되므로 "이대로 저장하면 정원보다 많이 탄 차량이 생겨요: "1호차" 은(는) 정원 5명인데 6명이 타 있어요(1명 넘어요). …"로 거절돼요. 먼저 **직접 옮기기**로 1호차의 한 명을 2호차로 옮긴 뒤 저장해요. 명단에서 사람이 지워져 이미 넘어 있던 차량은, 이번 저장으로 정원이 더 줄지 않으면(문구만 고치기 등) 막지 않아요.
  - 고치기 전 목록은 `people_log`에 `op = 'CARS'`로 남아요(되살리기는 아래 **실수로 지웠을 때**).
- 프로젝터 보기에서는 이 칸이 숨겨져요.
- 초기화 칸의 **전체 초기화**는 **탑승 차량도 함께 비워요**(손님만, 운전자 지정·차량 목록은 그대로).
- **명단 전체 삭제** 전에 받는 백업 파일(`워크숍_백업_…csv`)과 **보이는 명단을 엑셀 파일로 받기** 파일에 **탑승 차량** 칸이 있어요(손님은 차량 이름, 운전자는 "1호차 · 문구(운전)"). 받기 직전에 차량 정보를 새로 받아요. 한눈에 보기와 분류 단추의 차량도 이 칸이 받은 자료를 써요.
- 명단에서 한 사람을 지울 때 그 사람이 운전자면 확인 문구에 "1호차 운전자예요. 지우면 그 차량은 운전자 없음이 돼요…", 손님이면 "1호차에 타 있어서, 지우면 그 차량 인원이 1명 줄어요."가 덧붙어요.
- 시험하려면 `bash tests/car_db_test.sh`를 돌려요. 내 컴퓨터에 임시 Postgres를 띄워서 하므로 운영 DB에는 닿지 않아요(Postgres 도구가 `/opt/homebrew/bin`에 있어야 하고, 다르면 `PG_BIN=/경로/bin bash tests/car_db_test.sh`). 1분 안쪽이 걸려요.

- [ ] **주간 점검이 잘 돌고 있는지** 저장소 **Actions** 탭 → **주간 점검**에서 최근 실행이 초록색인지 봐요. 월·목 새벽에 Supabase에 요청을 보내 일시정지(1주일 동안 안 쓰면 멈춤)를 막아요. 응답이 이상하면 저장소에 이슈가 열려요.
- [ ] **관리자 비밀번호**가 무작위 16자 이상인지 확인해요. 틀려도 늦추지 않으니 길이가 유일한 방어예요. 짧으면 SQL Editor에서 바꿔요(위 **처음 한 번 설정** 2번).
- [ ] **행사장 와이파이와 사내망**에서 휴대폰으로 참가자 화면을 열어 로그인까지 해 봐요. 화면에 "필요한 파일을 받지 못했어요"가 나오면 그 망이 사이트 주소(`github.io`)나 `*.supabase.co`를 막는 거예요(LTE로 쓰게 안내). Supabase 연결 파일은 저장소의 `supabase.js`에서 받아서 `cdn.jsdelivr.net`은 막혀도 돼요.
- [ ] **SQL을 다시 Run했다면** 결과에 `WARNING: anon 의 제한 시간을 바꾸지 못했어요`가 없는지, `select rolconfig from pg_roles where rolname = 'anon';`가 `{statement_timeout=8s}`인지 확인해요.
- [ ] **명단 확정:** 안 오는 사람은 뽑기 전에 지워요(팀 인원이 어긋나지 않게). 임원 직급·성별이 비어 있지 않은지 분류 단추로 봐요.
- [ ] **DB를 이 사이트 판에 맞추기:** 사이트를 새로 올렸으면 Supabase **SQL Editor**에서 [`supabase.sql`](supabase.sql) **전체**를 다시 Run해요(`'여기를-바꾸세요'`는 그대로 두면 비밀번호가 유지돼요. 명단·기록은 지워지지 않아요). 그래야 **자동 섞기**(DB 함수 `admin_shuffle`)와 **아침 메뉴 초기화**(`admin_clear('menu')` 한 번)가 새 방식으로 동작해요. 안 하면 팀·탑승 차량 자동 섞기는 "DB가 아직 새 버전이 아니에요"만 뜨고, 방 자동 섞기와 아침 메뉴 초기화는 예전 방식으로 대신 해요. Run한 뒤 관리자 페이지에서 **팀 자동 섞기 · 안 뽑은 사람만**을 눌러 확인 상자가 뜨는지 보고 **취소**하면 점검 끝이에요.
- [ ] **시험으로 뽑은 기록 정리:** 시험 삼아 뽑거나 골랐으면 진행자 화면 맨 아래 **초기화** 칸의 **전체 초기화**로 여섯 항목(팀·방·아침 메뉴·점심·자유시간·탑승 차량)을 한 번에 지워요. 한 항목만 지우려면 같은 칸의 **○○ 초기화**를 써요. 명단·일정표·차량 목록(운전자)은 그대로예요. ⚠️ 마감(11/25(수) 15시) 뒤에 지우면 참가자가 다시 고르지 못해 진행자가 직접 넣어야 하니, 정리는 **마감 전에** 해요.
- [ ] **방 뽑기 전:** 명단 전원에게 성별이 들어 있는지 분류 단추로 봐요(성별이 없으면 방을 못 뽑아요). 시험 삼아 방을 뽑았으면 초기화 칸의 **방 초기화**로 지워요.
- [ ] **탑승 차량 전:** ⚠️ 처음 차량 목록에는 **운전자와 문구가 비어 있어요.** 관리자 페이지 **탑승 차량 → 차량 목록 고치기**에서 차량마다 운전자를 명단에서 고르고, 문구(예: '○○님 차량')를 적고, 정원은 비워 둔 채(자동·반씩) **뽑기 전에** 저장해요(위 **배포 뒤 처음 한 번**). 안 오는 사람은 뽑기 전에 명단에서 지워요(자동 정원이 명단 인원으로 계산돼요). 시험 삼아 뽑았으면 초기화 칸의 **탑승 차량 초기화**로 지워요(**전체 초기화**도 차량까지 비워요. 운전자 지정은 그대로). 차량 뽑기도 **11월 25일(수) 15시에 마감**돼요. 참가자에게 그 전에 뽑으라고 알리고, 마감 뒤에는 관리자 페이지 **탑승 차량** 칸에서 **아직 안 뽑은 사람**이 남았는지 보고 **직접 옮기기**로 인원이 적은 차량에 넣거나, **탑승 차량 자동 섞기 · 안 뽑은 사람만**으로 한 번에 넣어요.
- [ ] **행사 당일:** 진행자 화면을 **프로젝터 보기**로 띄워 두고 "마지막 갱신" 시각이 계속 바뀌는지 봐요.
- [ ] **일정표·점심·아침 메뉴**를 마지막으로 확인해요. 그림 파일(`menu_*.jpg`, `lunch_*.jpg`)은 행사 전에 확정하고 행사 중에는 바꾸지 않아요.
- [ ] **백업:** 진행자 화면 명단 관리에서 **보이는 명단을 엑셀 파일로 받기**(조건 없이)를 눌러 받고, 일정표 글도 복사해 회사 드라이브 등 비공개 위치에 둬요. 뽑기가 끝난 직후에도 한 번 더 받아요.
- [ ] **행사 뒤:** 프로젝터·공용 PC에서는 진행자 화면 맨 위 **마지막 갱신** 줄의 **이 기기에서 비밀번호 지우기**(휴대폰에서는 **비밀번호 지우기**)를 눌러요(비밀번호가 그 브라우저에 남아 있어요).
- [ ] **행사 뒤 개인정보 정리:** 필요한 명단·아침 메뉴 집계를 받아 둔 뒤 진행자 화면에서 **명단 전체 삭제**를 하고, SQL Editor에서 `truncate people_log;`를 해요. 그러면 실명이 DB에 남지 않아요. 차량 목록의 **문구와 운전자**도 비워요(관리자 페이지 **탑승 차량 → 차량 목록 고치기**에서 문구를 지우고 운전자를 '운전자 없음'으로 바꿔 **저장** — 명단을 지우기 **전에** 해요. 운전자가 명단에서 지워진 뒤에는 '운전자 없음'으로 바꿔 저장하면 돼요).

## 실수로 지웠을 때(되살리기)

DB가 명단의 줄이 바뀌거나 지워질 때마다 예전 값을 `people_log` 표에 남겨요(참가자·진행자 화면은 이 표를 못 읽어요).

- **명단 전체 삭제를 잘못 눌렀을 때:** Supabase 대시보드 → **SQL Editor**에서 아래를 Run하면 지운 사람들이 팀·아침 메뉴까지 그대로 돌아와요. 지운 시각 이후에 지워진 줄만 되살리도록 시각을 고쳐 쓰세요.

  ```sql
  insert into people (id, dept, name, title, gender, team, picked_at, menu, room, activity, lunch, car, car_at) overriding system value
  select x.id, x.dept, x.name, x.title, x.gender, x.team, x.picked_at, x.menu, x.room, x.activity, x.lunch, x.car, x.car_at
  from people_log l, jsonb_populate_record(null::people, l.old) x
  where l.op = 'DELETE' and l.at > now() - interval '30 minutes'   -- 최근 30분 안에 지운 줄
  on conflict do nothing;
  ```

- **초기화(전체 초기화·○○ 초기화)를 잘못 눌렀을 때:** 비우기 전 값이 `op = 'UPDATE'`로 남아 있어요(초기화는 백업 파일을 받지 않아요). SQL Editor에서 두 단계로 되살려요. 초기화 뒤에 참가자가 새로 고른 것은 초기화 전 값으로 덮이니 **누른 직후에** 해요.
  1. 초기화한 시각 찾기 — 전체 초기화는 몇 초 안에 시각이 **최대 5개**(항목 하나는 1개) 몰려 나와요(이미 비어 있던 항목은 바뀐 줄이 없어 기록도 없어요). 그 무리의 **가장 이른 시각**을 복사해요.

     ```sql
     select at, count(*) from people_log where op = 'UPDATE' and at > now() - interval '1 hour' group by at order by at desc limit 10;
     ```

  2. 아래 `'여기에-시각'`(두 군데)을 그 시각으로 바꿔 Run하면, 그 시각부터 **10초 안**에 바뀐 줄만 초기화 전 값으로 돌아가요. 되살릴 칸을 **초기화한 항목만** 남겨 쓰세요. 항목 하나만 초기화했다면 아래 첫 번째처럼 그 칸만 `set` 하고(예: 아침 메뉴만 → `menu = x.menu`; 점심 `lunch`, 자유시간 `activity`, 방 `room`, 팀 `team, picked_at`, 탑승 차량 `car, car_at`), **전체 초기화**를 되살릴 때만 두 번째처럼 여섯 칸을 모두 써요.

     ```sql
     -- 항목 하나만 초기화했을 때(예: 아침 메뉴)
     update people p set menu = x.menu
     from (select distinct on (x.id) x.*
           from people_log l, jsonb_populate_record(null::people, l.old) x
           where l.op = 'UPDATE' and l.at >= '여기에-시각'::timestamptz
             and l.at <  '여기에-시각'::timestamptz + interval '10 seconds'
           order by x.id, l.at) x
     where p.id = x.id;
     ```

     ```sql
     -- 전체 초기화를 되살릴 때(여섯 칸 모두)
     update people p set team = x.team, picked_at = x.picked_at, menu = x.menu, room = x.room,
                         activity = x.activity, lunch = x.lunch, car = x.car, car_at = x.car_at
     from (select distinct on (x.id) x.*
           from people_log l, jsonb_populate_record(null::people, l.old) x
           where l.op = 'UPDATE' and l.at >= '여기에-시각'::timestamptz
             and l.at <  '여기에-시각'::timestamptz + interval '10 seconds'
           order by x.id, l.at) x
     where p.id = x.id;
     ```

     - 초기화 뒤 10초 안에 일어난 다른 변경이 있으면 같이 되돌아갈 수 있어요. 되살린 뒤 명단 표와 한눈에 보기에서 맞게 돌아왔는지 확인하세요.
     - ⚠️ **운전자는 `car`가 비어 있어야 해요**(운전자는 차량이 따로 정해져 있고 손님으로 들어가지 않아요). 탑승 차량을 되살린 뒤 운전자 이름 줄의 차량 칸이 `-`인지 확인하고, 값이 들어갔으면 관리자 페이지 **직접 옮기기**에서 비워 주세요.
- **자동 섞기(○○ 자동 섞기 · 안 뽑은 사람만 / ○○ 전부 새로 섞기)를 잘못 눌렀을 때:** 섞기도 바뀌기 전 값이 `op = 'UPDATE'`로 남아요. 섞기 한 번은 DB에서 한 번에 처리돼서 기록의 시각(`at`)이 **모두 같아요**. 위 1번 SQL로 그 시각(바뀐 사람 수만큼 몰린 한 줄)을 찾고, 아래 `'여기에-시각'`을 바꿔 Run하면 섞기 전으로 돌아가요. **전부 새로 섞기**는 한 사람 기록이 두 줄(비우기·새로 정하기)이라 `order by` 의 `(x.team is null)` 이 비우기 전 값을 고르게 해요. 방은 `team, picked_at` 대신 `room`(줄 끝 `(x.room is null)`), 탑승 차량은 `car, car_at`(`(x.car is null)`)으로 바꿔 써요. 섞은 뒤 참가자가 새로 뽑은 것은 섞기 전 값으로 덮이니 **누른 직후에** 해요.

  ```sql
  -- 예: 팀 자동 섞기를 되돌릴 때
  update people p set team = x.team, picked_at = x.picked_at
  from (select distinct on (x.id) x.*
        from people_log l, jsonb_populate_record(null::people, l.old) x
        where l.op = 'UPDATE' and l.at = '여기에-시각'::timestamptz
        order by x.id, (x.team is null)) x
  where p.id = x.id;
  ```

- **일정표를 잘못 고쳐 저장했을 때:** 고치기 전의 글이 `op = 'SCHEDULE'`로 남아 있어요. SQL Editor에서 아래를 Run하면 예전 글을 최근 것부터 볼 수 있어요. 원하는 글을 복사해 **일정 고치기**에 붙여넣고 저장하세요.

  ```sql
  select at, old->>'value' as 일정표 from people_log where op = 'SCHEDULE' order by at desc;
  ```

- **차량 목록을 잘못 고쳐 저장했을 때:** 고치기 전의 목록이 `op = 'CARS'`로 남아 있어요. 아래를 Run해 예전 목록(JSON 글)을 보고, 관리자 페이지 **차량 목록 고치기**에서 그 값대로 다시 입력해 저장하세요.

  ```sql
  select at, old->>'value' as 차량목록 from people_log where op = 'CARS' order by at desc;
  ```

- 기록은 쌓이기만 해요. 행사가 끝나고 필요 없으면 SQL Editor에서 `truncate people_log;`로 비워요(일정표 기록도 같이 지워져요).

## 알아둘 점

- 참가자 화면에는 비밀번호가 없어요. **다른 사람의 부서와 이름을 아는 사람은 그 사람 대신 메뉴를 고르거나 바꾸거나(마감 전까지) 팀·방을 뽑거나 차량을 뽑거나(마감 전까지) 자유시간을 바꿀 수 있어요.** 워크숍용으로 일부러 단순하게 만들었어요.
- 일정표는 명단에 있는 사람으로 로그인해야 보여요(다른 사람의 부서와 이름을 아는 사람도 볼 수 있어요). 외부에 알리면 안 되는 내용은 적지 마세요.
- 팀을 뽑은 사람은 **같은 팀 사람들의 이름·직급·부서**를, 방이 정해진 사람은 **같은 방 사람들**을 볼 수 있어요(그 사람의 부서와 이름을 아는 사람도 볼 수 있어요). 전체 명단은 진행자 화면에서만 볼 수 있어요. 명단 파일은 이 공개 저장소에 올리지 마세요(`roster*` 파일은 `.gitignore`에 들어 있어요).
- 탑승 차량도 같아요. 차량이 정해진 사람은 **같은 차 사람들의 이름·직급·부서**를 보고, **모든 차량의 운전자 이름**(직급·부서 포함)과 차량 문구는 로그인한 누구에게나 보여요(차량 화면이 차량 목록을 함께 받아요). 문구에는 알려져도 되는 말만 적어요.
- 휴대폰은 받은 파일을 10분쯤 기억해요. 그림 파일(`menu_*.jpg`, `lunch_*.jpg`)처럼 주소에 `?v=`가 없는 파일을 바꾸면, 그동안은 예전 것이 보일 수 있어요. 꼭 바꿔야 하면 파일 이름을 바꿔 올려요.
- Supabase 무료 프로젝트는 1주일 동안 쓰지 않으면 일시정지돼요. **주간 점검**(`.github/workflows/weekly.yml`)이 GitHub 서버에서 월·목 새벽 3시 17분에 DB에 요청을 보내 막아요(PC가 꺼져 있어도 돼요). 그래도 멈추면 대시보드에서 **Restore**를 누르면 다시 쓸 수 있어요(몇 분 걸려요).
- 공개 저장소의 예약 실행은 저장소에 **60일 동안 변화가 없으면 GitHub이 꺼요.** 행사 뒤에도 계속 쓰려면 가끔 Actions 탭에서 켜져 있는지 봐요.
- 참가자 화면은 비밀번호가 없어서, 부서 목록을 보고 흔한 이름을 대입해 맞히면 그 사람의 팀 사람들 이름까지 볼 수 있어요. 더 막아야 하면 현장에서만 알려 주는 **참가 코드**를 추가하는 방법이 있어요(참가자가 코드를 한 번 더 넣어야 해요).
