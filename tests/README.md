# 로컬 시험 환경

운영 Supabase에 **한 건도 닿지 않고** 실제 `supabase.sql` 함수로 화면을 돌려 보는 환경이에요.
로컬 postgres(포트 54329) + 대리 서버(저장소 정적 파일 + `/rest/v1/rpc/<함수>`) + Playwright 도우미로 이뤄져요.

## 처음 한 번

```sh
cd tests && npm install      # playwright, pg. 브라우저는 설치된 Google Chrome 을 써요(없으면 npx playwright install chromium)
npm test                     # = node run.mjs smoke : DB 올리기 → 명단 → 서버 → 브라우저 시험 → DB 끄기 (약 2초)
```

## 명령

| 하고 싶은 일 | 명령 |
|---|---|
| DB 켜기 + `supabase.sql` 새로 적용 | `node run.mjs db-up` |
| DB 끄기 | `node run.mjs db-down` |
| 견본 명단 다시 넣기 | `node run.mjs seed` |
| 일부는 이미 뽑은 상태로 | `node run.mjs seed --picked` |
| 성별 없는 1명 포함 | `node run.mjs seed --no-gender` (둘을 같이 써도 돼요) |
| 대리 서버만 | `node run.mjs server [포트]` (기본 54330) |
| 손으로 눌러 보기: DB+명단+서버 한 번에 | `node run.mjs dev` (Ctrl-C 로 전부 정리) |
| 관리자 페이지 초기화 칸 시험 | `node run.mjs reset` (= `npm run test:reset`, 약 1분) |
| 관리자 페이지 자동 섞기 시험(팀·방·탑승 차량 × 안 뽑은 사람만·전부 새로, 아침 메뉴 초기화) | `node run.mjs shuffle` (= `npm run test:shuffle`, 약 1분 30초) |
| 자동 섞기 DB 시험(임시 Postgres, 이 환경과 따로) | `bash tests/admin_shuffle_db_test.sh` (저장소 맨 위에서, 약 1분 30초. `QUICK=1`이면 통계 판 수를 줄여 빨리) |
| 발표용 뽑기 화면 시험 | `node run.mjs draw [시나리오 번호...]` |
| 발표용 점수판 화면 시험(입구·점수 주기·연타·새로 고침·두 탭·저장 실패·연습·초기화·움직임 줄이기·화면 안 들어가는지·소리 요청·키·이름) | `node run.mjs score [시나리오 번호...]` (= `npm run test:score`, 약 4분) |
| 관리자 페이지 정렬 시험(차량 열·분류 단추·엑셀 열·마감 안내(마감 전·후·열어 둔 채 넘김)·자유시간 복사·발표용 링크·프로젝터 보기(차량 안 받기)·390px(누르는 자리·표 안 넘침)·빠른 추가 오류·칸 통일·칸 순서·열림 기억·아침 메뉴/점심/자유시간 세 칸 같은 구성과 직접 고치기 토글·복사) | `node run.mjs admin` (= `npm run test:admin`, 약 1분) |

`reset.mjs`(초기화 시험): 일곱 항목(팀·방·아침 메뉴·점심·자유시간·탑승 차량·팀 점수)과 차량 목록·운전자·일정표를 채운 뒤, 전체 초기화(취소/확인, 점수도 0점으로, 확인 문구 끝 `점수 N팀`)·항목별 초기화 일곱 개가 그 항목만 비우는지(사람 칸 여섯 개는 팀 점수를 안 건드리고, **점수 초기화**는 `admin_clear(score)` 한 번으로 점수만 0이고 사람 칸·일정표·차량 목록은 그대로), 확인은 confirm 한 번뿐이고 백업 상자·파일 받기가 없는지, 마감 뒤 확인 문구(`page.clock.setFixedTime`으로 화면 시계만 마감 뒤로 — 서버 `choices_closed()`는 실제 시계), 초기화 뒤 참가자 메인이 "아직 안 골랐어요/안 뽑았어요"인지, 중간 실패(`page.route`로 `admin_clear(lunch)` 한 번 실패 → "아직 남은 것: 점심·자유시간·탑승 차량·점수", 점수 단계만 실패)·점수 함수가 없는 예전 DB(`server.missing`으로 `score_state`만 404: 점수 초기화는 안내만, 전체 초기화는 점수 단계를 그냥 지나감) 뒤 다시 눌러 이어지는지를 봐요. 예전 DB 에서 점수 단계를 건너뛴 전체 초기화의 끝 문구는 "점수 비움"이라 하지 않고 "점수 단계는 DB가 아직 새 버전이 아니라 건너뜀"이라고 사실대로 알려요.

`score.mjs`(발표용 점수판 `score.html` 시험, 시나리오 번호로 골라 돌려요 `node run.mjs score 1 6`; 모든 context 에 `guardNetwork`를 걸어 운영 요청 0건을 확인하고 견본 명단·시험용 비밀번호만 써요. 흔들리지 않게 고정 대기 대신 `window.__score`(`phase`·`busy`·`animating`·`shown`·`server`·`spinning`·`calls`·`errorKind` 등)와 `window.__scoreAudio`(소리 요청 기록 `{dir:'up'|'down'|'test', played, muted, ms}`·`cuts`·`state`)를 기다려요):
1) 입구: 비밀번호 전에는 점수판 DOM·서버 요청이 없음(저장된 관리자 비밀번호가 있어도), 틀림(빨강 `wrong`)·통신 오류(노랑 `offline`, "틀렸다는 뜻은 아니에요")·서버 오류(`server`) 구분, 같은 탭 새로 고침은 다시 안 묻고 서버에 다시 확인·새 탭은 다시 물음, 잠그기(확인 상자·취소·기억 삭제), 잠근 뒤 새 화면이 늦게 와도 점수 받기(`score_state`·`board_state`) 요청이 더 안 나감, 비밀번호가 바뀌면 입구.
2) 네 팀 +/−·직접 입력 더하기/빼기·거절 입력·한도와 DB(`team_scores`)=화면, 서버 함수 `score_add`(동시 20번 합산·오류 문구·±1,000,000/±1,000,000,000 경계·`anon`은 표를 직접 못 읽고 못 씀·`supabase.sql` 다시 적용해도 점수 유지).
3) 연타·Enter 두 번·키 반복(repeat)이 요청 한 번(응답을 느리게), 연출 중 같은 팀 연속·다른 팀 바로 이어서(두 팀이 동시에 돎), 마지막 값으로 정확히 멈춤, 연출 길이 1.8~2.5초(+999,999여도). **세어 올라가기/내려가기**: 네 팀을 한꺼번에 줘 놓고 15ms 마다(`setInterval`, `requestAnimationFrame` 대기 없음) 팀별 표본(`__score.display`·`data-cur`·자리별 칸의 `data-d`/`.roll`/변환/위치)을 모아, 0→+100·1,200→+100·20→+10·130→−50·99→100·1,000→999·5→−45·0→+999,999 가 각각 이전 값과 새 값 **사이**에서 **한 방향으로만**(올릴 땐 늘고 내릴 땐 줆) 움직이고 끝에서 정확한 값(`display`·`shown`·`data-cur`·DB)에 멈추는지, 연출 길이 1.8~2.5초, 마지막 8걸음(차이가 작으면 모든 걸음)이 건너뛰지 않고 보이는지, 처음 빠르고(절반이 0.7초 안) 끝에서 느린지(마지막 10%가 0.6초 넘게), 일의 자리가 올릴 땐 위로·내릴 땐 아래로 굴러가는지, **바뀌지 않는 자리가 가만히**인지(1,200→1,300 도중 천의 자리는 `'1'`·굴러가지 않음·x 위치 그대로, 20→30 도중 28 이하에서 십의 자리 그대로), 자릿수가 바뀔 때(맨 윗자리가 서서히 나타나고 사라짐·쉼표 없음·마이너스 표시가 0 아래에서만), 센 내내 점수가 칸 밖으로 안 나가는지(허용 오차 0), 세는 도중 새 점수(+100 → +50 → −100)가 0 으로 되돌아가지 않고 지금 값에서 이어서 가며 마지막 값 50 에 정확히 멈추는지.
4) 새로 고침 뒤 점수 유지(연출 중·저장 중, 서버엔 한 번만 들어감).
5) 두 브라우저: 다른 쪽 점수가 5초쯤 뒤 반영(소리 요청 0)·동시에 줘도 합산·연출 도중 폴링이 연출을 안 덮음·연출이 도는 내내 `requestAnimationFrame` 예약이 최대 1개(끝에서 다시 맞추는 연출이 루프를 안 늘림).
6) 저장 실패: 서버 400 거절(점수 그대로·빨간 오류·다시 할 수 있음)·응답 끊김(서버 미반영, 자동 재시도 없이 `score_add` 한 번, "아직 반영되지 않았어요, 늦게 반영될 수도 있어요"로 단정하지 않음)·서버엔 반영됐는데 응답만 끊김("저장돼 있었어요", DB엔 한 번만)·점수를 처음 못 받음.
6.1) 응답이 끊긴 요청이 늦게 서버에 도착(`page.route`로 브라우저엔 `abort`, 서버엔 몇 초 뒤 같은 본문 전송): 안내 뒤 같은 점수를 다시 눌러도 DB 는 한 번(두 요청의 `p_req` 같음)·다시 누른 것이 먼저 도착해도 늦은 요청이 안 더해짐·번호는 (팀, 점수)마다 따로 기억돼 **그 사이 다른 점수·다른 팀을 줘도 남음**(F: +50·−10 둘 다 끊긴 뒤 다시 누르면 각자 옛 번호, 성공한 번호만 지워짐 / G: 늦은 요청이 먼저 도착한 뒤 −10 을 주고 +50 을 다시 눌러도 한 번만)·기억하지 않은 다른 (팀, 점수)는 새 번호(옛 요청이 나중에 반영되는 알려진 위험)·서버 400 거절 뒤엔 새 번호.
6.2) 요청을 23초 붙잡아(브라우저는 20초에 포기) 같은 경로 시험(약 24초).
6.3) DB 직접 `score_add(…, p_req)`: 같은 번호 순차·동시 12번·번호 둘 섞어 동시에 한 번씩, 한도 초과로 실패한 번호는 기록 안 돼 다시 쓸 수 있음, 잘못된 형식(7자·65자·공백·따옴표·한글·점·빈 글자·줄바꿈) 오류, 24시간 지난 줄 삭제, `anon` 직접 읽기·쓰기 차단·RLS, 점수·전체 초기화가 번호를 안 지움(초기화 뒤 늦게 온 같은 요청이 안 더해짐), `supabase.sql` 다시 적용해도 점수·번호 유지·옛 세 인자 `score_add` 정리, 대리 서버가 `p_req`를 그대로 넘김.
6.4) `+N` 표시·소리·도는 방향은 내가 준 점수 기준(다른 탭이 방금 같은 팀을 바꿔 화면과 서버가 달라도), 최종 표시값은 서버 값, 폴링으로 따라올 때만 차이를 표시(소리 없음).
6.5) 직접 입력 부호: 더하기는 입력한 부호 그대로·빼기는 늘 마이너스(`-50`·`50`·`+50` 모두), Shift+Enter, `-1,000,000`이 입력 칸에 잘리지 않고 들어감(`pressSequentially`로 `maxlength` 적용), 저장 중에 쳐 둔 다음 숫자는 저장이 끝나도 남고 보낸 값 그대로면 비워짐.
7) 연습 모드: 입구 확인 외 DB 요청 0건, 연출·소리·되돌리기는 동작, 새로 고치면 0점.
8) 관리자 페이지 **점수 초기화**가 열려 있는 점수판에 따라옴(소리 없음), 낡은 되돌리기(내가 준 것이 아닌 변화로 그 팀이 맞춰지면 되돌리기 단추·`#undoWhat` 비움, `U` 요청 0건·다른 팀 변화로는 안 지워짐).
9) 움직임 줄이기: 굴러가는 칸(두 숫자가 든 `strip`·`.roll`)·`animating`이 한 번도 없이 바로 새 점수(`display`·`data-cur`도 바로 그 값, 중간 값 없음), 소리는 600ms.
10) 1920×1080·1280×720에서 네 팀·네 점수·조작부가 화면 안·서로 안 겹침(처음·도는 중·999,999,999와 −123,456,789·오류 상자·이름 많은 팀·아주 긴 이름·이름 숨김·연습), 점수 글자가 이름·조작부보다 큼(9자리 점수가 팀 이름 글자보다 약간 작아지는 것은 허용하고 알려만 줘요). 자릿수가 바뀌는 연출(1→3→6자리·음수·줄어듦)을 이어서 하는 내내 네 점수가 점수 칸 밖으로 한 번도 안 나가야 해요(허용 오차 0, 튀어 오르는 강조까지 포함 — 4자리 점수에서 `hitUp` 곡선이 끝점을 넘어 튀는 것까지 잡도록 시나리오 3에서도 같은 감시를 해요).
11) 소리 요청 관측: 올릴 때 `up`·내릴 때 `down`·소리 시험 `test` 각 1건, 연달아 줄 때 이전 소리를 끊는 `cuts`, 끄면 `played:false`로 기록 유지, 새로 고친 뒤 첫 점수부터 요청·오디오 `running`, 연출 길이≈소리 길이, 소리를 켜면 "소리가 꺼져 있어서 안 들려요" 안내만 지워짐(다른 안내는 그대로).
12) 키보드(`1`~`4`·`Q W E`·`A S`·`Enter`/`Shift+Enter`·`U`·`M`·`H`)·입력 중엔 가로채지 않음·반복 키 무시(`M`·`H`를 누르고 있어도 한 번만)·되돌리기(반대 값·연출과 소리·한 번만)·팀을 안 고르고 주기.
13) 이름: 팀별·안 뽑힌 팀은 이름 없이·같은 이름은 (부서)·HTML 이 든 이름이 태그로 안 들어감·이름 숨기기 유지.

## 견본 명단 (`seed.mjs`)

29명: 남 20·여 9, 부서 6(`시험영업부`…`시험기획부`), 임원 4(대표이사·상무·이사·전무). 이름은 `견본가`, `견본나`, … `견본고`.
`--picked`는 id 1~12에 팀·아침, 1~10 중 성별 있는 사람에 방, 1~8에 점심, 1~6에 자유시간을 채워요(팀 균형을 맞춘 값이 아니라 화면 시험용).
코드에서는 `resetRoster(client, { picked, noGender })`, `applyPicked(client)`, `roster()`를 써요. `resetRoster`는 명단·변경 기록·일정표를 비우고 id를 1부터 다시 매겨요.

## 대리 서버 (`server.mjs`)

```js
import { startServer } from './server.mjs';
const server = await startServer({ port: 0 });   // 0 = 빈 포트 아무거나. server.url, server.calls(받은 rpc 기록 {fn,args,status,ms}), await server.close()
// 예전 DB 흉내: startServer({ port: 0, missing: ['admin_shuffle'] }) 또는 server.missing.add('admin_shuffle') — 그 함수만 404 PGRST202
```

- 저장소 루트의 정적 파일을 내줘요(`tests/`와 `.`으로 시작하는 것은 안 내줘요).
- `POST /rest/v1/rpc/<함수>`(`[a-z_]+`만): 로컬 DB에서 `set local role anon` 상태로 `함수(p_x := …)`를 불러요. 성공 200 + JSON(void 는 204), 함수에서 낸 오류는 400 + `{message, code, details, hint}`, 없는 함수·인자는 404 `PGRST202`. `anon`이 못 부르는 함수는 400(`42501`)이라 실제 권한도 그대로 시험돼요. 요청 제한 시간은 운영처럼 8초.
- 마감: `choices_closed()`는 실제 시계를 써요(2026-11-25 15:00 KST 이후에는 점심·아침·자유시간 고르기가 거절돼요). 그 뒤에 시험하려면 마감이 지난 상태가 정상 동작이에요.

## Playwright 도우미 (`helpers.mjs`)

```js
import { openTestBrowser } from './helpers.mjs';
const env = await openTestBrowser(server.url);    // { browser, context, guard, newPage(), close() }
const page = await env.newPage();
await page.goto(`${server.url}/board.html`);
// ... 시험 ...
env.guard.assertClean();                          // 허용 안 된 외부 요청이 있었으면 여기서 throw
await env.close();
```

이미 만든 context/page에는 `await guardNetwork(context, server.url)`만 걸면 돼요(새 context마다 따로 걸어야 해요. `launchBrowser()`도 따로 써요).

**운영 DB를 막는 방법(두 겹)**
1. `route('**/*')`: `https://*.supabase.co/**`는 경로·본문만 로컬 대리 서버로 넘겨 답을 돌려주고(운영으로는 연결하지 않음), 로컬 주소·`data:`·`blob:`·`about:` 말고는 모두 abort 하며 `guard.blocked`에 적어요. `assertClean()`이 이게 비어 있는지 확인해요. `guard.proxied`는 로컬로 돌린 요청 목록이에요.
2. Chrome 실행 인자 `--host-resolver-rules`로 `127.0.0.1`/`localhost` 말고는 이름 풀이 자체를 막아요(`route`에 안 잡히는 웹소켓도 막힘).

## 알아 둘 점

- 같은 context 의 페이지끼리는 `localStorage`를 공유해요. 관리자 화면은 비밀번호를 저장하므로, 로그인 실패를 시험하려면 새 context 를 써요(`smoke.mjs` 참고).
- 시험마다 상태를 맞추려면 `resetRoster`로 다시 넣어요. DB를 통째로 새로 만들려면 `db-up`(`buildSchema()`).
- 참가자 메인에서 방·팀 뽑기 단추(`#goRoom`, `#goTeam`)는 숨겨져 있어요(`hidden`). 로그인 확인에는 `#goMenu`를 써요.
- 화면의 `supabase.js`에 `integrity` 해시가 있어요. 대리 서버가 파일을 그대로 내주므로 문제없지만, 파일을 바꾸면 해시도 맞춰야 해요.
